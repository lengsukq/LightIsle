## 可重复的自动化门禁

从项目根目录执行：

1. Web：npm test --prefix apps/web；npm run build --prefix apps/web
2. Flutter：进入 apps/flutter，执行 flutter test --no-pub；flutter analyze --no-pub（如旧测试文件已有警告须单独标注）
3. Flutter 设备构建：flutter build macos --debug --no-pub；flutter build ios --debug --no-pub
4. Go：go test ./core/...
5. Git：git diff --check

**注意：iOS 签名构建通过不等于已运行真机；即便启动成功也不等于 NAS 登录、iCloud、RAW、投屏和后台备份真实场景通过。**

## 回归守则

- 「最近添加」严格使用服务端最近入库排序；「继续观看」严格使用当前账号未完成的播放进度。接口失败不能用按标题排序的数据冒充。
- 打开照片先展示清晰度受限的占位图，再显示原件；不能在原图下载/解码完成前把可见照片替换成黑屏转圈。
- 移出相册只修改关联；移入回收站明确需要原文件权限和确认；不能把两者混成同一操作。
- 根切换会取消/丢弃旧根媒体查询与预览，切换账号不复用他人的缓存与观看历史。
- P1 若缺乏真实设备/媒体/账号，只能标记为「软件实现与自动化完成，真机待验」，不能写「全验收通过」。
