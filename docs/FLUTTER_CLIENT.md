# Flutter 客户端（Android / iOS / macOS）

> 本文对应 `apps/flutter/` 的**当前实现与开发方法**。代码能力不等于真机验收；现状以 [STATUS](STATUS.md)、后续问题以 [ROADMAP](ROADMAP.md) 为准。

## 使用范围与平台差异

| 平台 | 用途 | 重要限制 |
| --- | --- | --- |
| Android | 文件/图库/影视、手动上传、照片前台备份与可选 WorkManager 后台照片任务 | 系统调度、存储权限和 OEM 后台限制必须实测；后台不覆盖视频 |
| iOS | 文件/图库/影视、照片/视频前台上传、RAW/Live Photo 资源处理 | iCloud 未下载原件与系统后台备份无完整自动保障 |
| macOS | 独立的 LightIsle Client，连接已有 NAS；宽屏侧栏 | 不是管理端、不创建 NAS 服务、不执行本机磁盘危险操作 |

**多硬盘**：读取用户的三类存储绑定，按 `rootID + generation` 定位对应盘；管理员逐盘设置成员额度。普通成员新根默认 100 GiB，同盘多分类共用。私人目录尚未实现全写入渠道硬配额（`enforcement=pending`），出错不换盘或绕过授权。

**2026-11-02 已有 P1 代码入口**：离线照片原件按 NAS 来源/稳定用户/根代际隔离缓存、RAW 扩展格式识别、iOS RAW/Live Photo 资源保存、AirPlay/PiP/DLNA 相关播放器与撤销保护。上述均需要对应设备验收；音乐未开发。

## 产品边界

Flutter 是现有 NAS 的用户客户端。Android、macOS、iOS 共用业务代码，窄屏底部导航，宽屏侧栏，支持系统浅深色、大字体、语义标签与键盘导航。macOS 应用名称为 **LightIsle Client**，使用独立 bundle ID，和已有 SwiftUI **LightIsle.app** 管理端区分。

NAS 仍只运行在 macOS arm64；原生管理端拥有 Go 服务生命周期，负责首任管理员初始化、共享根目录授权、可选的局域网 HTTPS 和本机备份恢复。Flutter 不另启 Go 服务，不增加首次注册或本机特权 HTTP 接口。退出客户端不会停止 NAS；退出原生管理端会停止 NAS。

## 登录状态保留

2026-10-27：默认在本机保留最近一次成功登录的有效会话，关闭、重启客户端后自动恢复。保存服务器来源、证书指纹、会话 Cookie 与服务端到期时间，**不保存密码，也不把会话写入 SharedPreferences、日志或 URL**。iOS/macOS 通过系统 Keychain 保存且关闭同步；Android 通过 Keystore 的独立 AES-GCM 密钥加密后保存，退出时删除密文和对应密钥。未引入新依赖。

启动先经原有 TLS/证书指纹校验，再向 `/api/v2/auth/me` 验证会话并读取当前账号与角色；不会把本机缓存的身份直接当成登录成功。自动连接最多等待 12 秒，其他 API 沿用原有超时。NAS 离线、网络超时或证书错误时保留会话，显示重试及“使用其他账号或服务器”。本机到期或 NAS 返回 401 时清除保存记录并要求重新登录；当前后端会话期限为 30 天，客户端不续长到期时间。

主动退出/切换服务器及修改密码后退出都会清除本机记录。若安全存储暂不可用，会显示解锁设备/检查存储后的重试提示，不伪装为已经保存或清除。Android 验证通过后重新绑定前台会话，保持同账号已有后台备份授权的原有规则；退出、切换账号和失效时会撤销原生后台备份。即使应用被系统杀掉、前台令牌丢失，也可以从原生加密配置清除旧授权、推进 Worker generation 并尽力取消旧任务；仅取消 WorkManager 超时但授权已持久删除时，退出仍可完成。新登录若安全保存之后的原生绑定失败，会回滚该次保存，避免下次重启意外登录；已有登录恢复失败则保留原记录供重试。

验证：登录/重启恢复、来源/指纹/令牌/期限约束、离线重试、服务端撤销、本机过期、离线退出、当前会话失效、保存失败恢复、原生绑定失败回滚、离线切换账号清理旧 Worker、退出清理失败不假报成功，以及持久化/后台会话操作串行化均已纳入 Flutter 测试；本机 Mac 的隔离 Keychain 服务已验证写入、读取、更新与删除。本轮追加复核：`flutter analyze --no-pub` 无问题、`flutter test --no-pub` 197 项通过、1 项跳过，Android arm64 Release APK 构建通过（保留既有 pdfx Kotlin 兼容警告）。Android/iOS 实机重启和设备锁定状态仍需设备验收。

## 移动端布局与手动上传

**2026-11-02 响应式审查和修复**：参照 Mac 原生管理端的连续画布、浮动侧栏和实体卡片，Flutter Mac Client 默认使用紧凑图标导航，在够宽的窗口中可展开/收起侧栏（`⌃⌘S`）；浮动侧栏胶囊高度随导航项收缩，不再拉伸到整窗高度。手机底栏在 320px/200% 字号下优先保留可访问的五入口图标和提示，输入键盘弹出时不遮挡页面。文件工具栏保留上传与新建文件夹的图标快捷入口，概览指标按实际栏宽换列，存储成员绑定的操作按钮在窄窗独立换行。高对比与减少动画时浮动导航及确认框改为不透明实体表面，避免模糊和文字对比度下降。图库/影院增加了带真实条目模拟数据的响应式滚动回归，修复 320px 影片海报标题/状态栏溢出；空状态在窄短屏减小无效留白。

本次不复制 Mac 管理端的宿主运维页面。所有改动只涉及 Flutter UI/测试，NAS API 与写入权限保持原样；新增 11 类二级页面的窄屏/大字号与桌面布局回归，并修复目录授权的磁盘下拉框在 320px/200% 字号下溢出。专项验证使用 `flutter test --no-pub test/layout_alignment_test.dart test/responsive_shell_test.dart test/media_responsive_content_test.dart test/secondary_responsive_test.dart`；静态检查使用 `flutter analyze --no-pub`。实际 Android/iOS 多设备、屏幕阅读器、输入法遮挡以及 Mac 窗口材质仍需 [真机验收](DEVICE_ACCEPTANCE.md)。

**第二轮视觉统一（2026-11-02）**：Flutter 不再单独挑选蓝白背景、卡片圆角或浅深色板，而直接使用 `nativeMac` 语义 Token 生成颜色与控件尺寸（`python3 scripts/sync-flutter-tokens.py --check`）。概览新增与 Mac 相同信息语义的设备摘要卡，桌面优先显示设备卡、手机优先显示个人空间入口；设置页桌面是原生风格的分栏功能卡，手机是连续分组列表。全局页面采用原生淡紫灰连续画布、轻微柔和渐变、实体白卡/深色卡和导航少量材质。地图底图配置/提示在窄屏改为可展开的独立滚动区域，离线照片、存储配额与授权说明在手机上折叠辅助文案（关键安全限制仍可在标题中识别）。

手机端浮动底部导航上缘保留 12dp 留白，让最后一张内容卡片与导航分开；导航仍位于系统底部安全区之上。

全局静态画布与路由内容使用独立重绘边界，二级页转场时复用已绘制的背景渐变。macOS 淡入转场的过渡底色设为透明，避免默认的 surface 白色短暂遮住画布。Widget 回归覆盖该路由转场；真实设备上的帧率与视觉观感仍需按下方清单验收。

新增 `test/dialog_responsive_test.dart` 覆盖目标文件夹选择、授权目录、相册命名和重置密码等弹窗；`test/secondary_responsive_test.dart` 覆盖 16 类二级页面和播放器错误场景，包括 Android/iOS 前台照片备份页，合成窗口尺寸为 320×568、375×812、600×840、1024×700，320px 包含 200% 字号。截图工具只在 `--dart-define=LIGHTISLE_CAPTURE_VISUALS=true` 时输出临时视觉审查文件到 `build/`（不提交图片到 Git）。其他媒体真实条目网格与五栏主题回归沿用上一轮测试；本机 Widget 合成数据不能证明实机动画/屏幕阅读器/第三方播放器兼容。

### 角色首页、设置与文件预览（2026-11-02）

- **管理员 Dashboard**：首先显示 Mac 连接/运行状态、处理器、内存、磁盘、网络及后台任务，再展示个人文件快捷入口。仍仅管理员读取 `/api/v2/system` 和 `/api/v2/tasks`。
- **成员 Dashboard**：个人文件、相册和影院入口优先，之后按物理根展示本人已入账用量和额度，**不能把账本用量称作真实整盘占用**；仅访问 `/api/v2/me/storage`。这两种角色由代码决定，服务端授权不变。
- **设置**：管理员显示成员、逐盘配额、通知、审计与维护；成员只有本人存储、文件/分享、连接及个人安全。桌面网格紧凑、手机使用紧凑的连续分组行；连接详情保留在个人身份卡中，辅助性说明折叠。
- **文件管理点击与右侧更多菜单**：点击文件仍然优先打开内置预览。图片和视频**共用相册的 `PhotoGalleryViewer`**，支持手势缩放、滑动切换、视频进度/前后 10 秒/倍速；文件目录内播放列表和连续播放只是同一个查看器的文件模式，不复刻播放器。文件模式隐藏相册收藏、元数据编辑与离线图库专属动作。文件行右侧的更多菜单保留下载、分享、复制/移动/重命名/回收站（按权限显示），另有“其他应用打开”。
- **PDF / 文本 / 其他格式**：PDF 继续由已依赖的 `pdfx` 在应用内查看、双指缩放、失败重试，右上角可保存原件或转系统应用；文本以只读 UTF‑8/带 BOM 的 UTF‑16 显示，编码不明则提示，不静默篡改字符。其他未识别格式保留不能预览的提示，通过右侧更多菜单选择保存或系统应用。外部打开用 `open_filex`，先经已鉴权 API 下载到应用私有临时目录，**绝不向外部 App 提供 NAS Cookie 或受保护源 URL**；大于 512 MiB 时拒绝临时外部打开，建议使用“下载”。临时副本后续按保留时限清理。
- **Live Photo 与字幕**：图库仍按同一目录/同名且拍摄时间接近的唯一 MOV 伴侣识别 Live Photo；播放动态片段时在当前照片上方呈现，播放完回到静态图，不切换相册索引。图库与文件管理视频共用 `video_player` 控件，可在本次播放加载本机 SRT/VTT；影院继续使用原有剧集、进度保存、服务端同名/嵌入字幕与 HLS/投屏处理，另增**本机 SRT/VTT 字幕导入**。不新增独立 `media_kit` 播放器，避免两套视频控件和插件；设备支持的容器、音轨、字幕与编码仍以真实平台验证为准。

上述 UI 适配和媒体格式选择策略已增加角色、文件复用与格式分类测试；字幕文件只在本机读取，最多 1 MiB，不上传。**测试通过仅表示 Widget/模拟 API 行为通过，不代表所有 Android/iOS/macOS 音视频编解码、后台/Live Photo 资源或系统文档应用交接已真机验收**。详见 [设备验收](DEVICE_ACCEPTANCE.md)。

### 共用实现收敛（2026-11-02）

- 图库与文件管理统一 `PhotoGalleryViewer`，文件模式只提供文件夹内媒体浏览和连续播放，不再保留平行开发的文件视频弹窗。
- 相册视频、影院和本地离线视频的**倍速选项控件**统一由 `MediaPlaybackSpeedPicker` 维护；各播放页保留自己的播放状态、HLS/进度与出错恢复，不强行合并业务控制器。
- 离线照片、离线视频的 NAS origin、证书指纹、账号、硬盘代际隔离哈希统一用 `offlineMediaScopeId`；照片库仍要求稳定的 `uid:` 账号编号，影片库保留自己的账号输入校验及本地索引规则，避免复用引起旧离线库失联。
- 暂不合并文件目录 ZIP、单文件下载、媒体原件导出与电视投屏使用的临时分享：这些动作的授权、大小限制、生命周期与安全边界不同，仅可在边界审查后抽取底层的共同搬运逻辑。

**二次收敛（2026-11-02）**：

- 图库详情弹窗不再持有独立的 `VideoPlayerController`、图片缩放控制器和独立进度条。媒体区域直接采用 `photo_gallery_viewer.dart` 的 `PhotoMediaImage` / `PhotoMediaVideo`，相册归属、EXIF、个人/共享收藏编辑继续由详情弹窗负责。
- `files_page.dart` 中的原件导出、批量导出和系统文档保存逻辑移到 `file_export_service.dart`，文件名规则统一由 `file_name_validation.dart` 提供。限时匿名分享弹窗移到 `file_share_dialog.dart`；图库查看器不再依赖整个文件管理页面，避免相互导入。文件行单击仍是内部预览，右侧更多菜单的分享、下载、系统打开均保持不变。
- `offline_index_io.dart` 复用离线照片/影片 JSON 索引的原子写入及失败清理；原索引路径、JSON schema、照片 `.tmp` 与影片 `.new` 后缀、账号/服务器/硬盘隔离及大小/hash 校验都没有改变。新增回归覆盖原索引解码、覆盖写入及编码错误不破坏旧索引。
- `AndroidPipSession` 为影院和本地视频共用同一套原生通道、进入画中画超时和失败复原规则；**使用后进先出的监听注册**，在影院页面打开本地视频页面并返回时恢复原监听，而不由子页面误删父页面监听。影院自行保存播放进度，离线播放器保持本机播放与生命周期行为。
- **刻意不合并**普通文件上传和 Android 原片备份的高层状态机：前者允许同目录自动改名与手动暂停/继续；后者严格绑定原路径、Wi-Fi/权限、后台调度、原片 SHA-256 与失败游标。未来如继续精简，只抽出可以验证的底层服务端上传会话/偏移检查，禁止改变原有冲突及完整性语义。

- 后续将 `FileUploadService` 从 `FilesPage` 剥离，专管原件 SHA-256、上传任务恢复/创建、服务端偏移确认、分块发送、完成/中止与持久化续传提示；`FileUploadJob` 统一暂停门闩、继续、取消、重试的生命周期。页面只负责选择文件、展示进度、错误及返回确认。旧 `lightisle_upload_v3_` 身份规则、同目录改名、根代际保护均不变，新增了暂停中取消及随机范围读取测试。

- `photo_backup_hash.dart` 为 Android/iOS 前台原片备份提供独立可测试的有界 SHA-256 流读取、每块摘要、前后文件身份核验及取消回调。后台 WorkManager、游标持久化和失败注册仍使用原有状态机，不把大小相等当作持久备份成功。

## 手机原片备份的校验与遗漏

- Android 前台仍受原片 2GiB 上限约束，后台仅备份照片且大于 100MiB 需要前台处理；这些遗漏不计为成功。iOS 原片准备上限为 32GiB，iCloud 尚未落盘的原片不会被自动下载。
- 2GiB 以内继续使用完整 SHA-256 接口。大于 2GiB 的 iOS 原片，在同一次本地读取中产生完整摘要与 4MiB 分块摘要；NAS 逐块读取实际文件，要求全部范围、长度、摘要及文件版本一致，每块前后检查暂停状态。NAS 同时最多进行两次哈希读取，不能把 HEAD 大小相等当成校验成功。
- 大原片分块校验目前只开放给通过已打开文件描述符确认的本机 APFS；其他磁盘格式明确返回 `verification_filesystem_unsupported`。文件版本由物理身份、修改/变更时间、大小等组成，不能把它当作文件系统快照；不承诺在内核磁盘读取阻塞时立即取消。
- 单张原片缺失、iCloud 未落盘或本机原片读取失败，会登记为未完成并继续后续资产；权限撤销、服务/缓存故障、取消、NAS 网络或写入/校验失败仍停止本轮。未解决遗漏存在时不写完整备份时间，扫描到末尾后可从最新照片重新检查重试。
- 每个账号/服务器/设备和照片或视频模式仅保留一份失败集，最多 512 条匿名资产摘要，超出部分保留遗漏数量；图库版本改变或重新全扫会重建该集合。失败记录持久化失败时不得继续推进页游标。手机原件始终保留，真实大视频、退后台和外接盘仍需设备验收。

## 连接

1. 打开现有 `LightIsle.app`，完成管理员初始化；局域网 HTTP 会默认自动开启，必要时可在 Mac 设置中切换 HTTPS 或关闭访问。
2. Flutter 输入 Mac 显示的服务地址和已有账号。
3. macOS 本机可用 `http://127.0.0.1:16666`；手机需要使用可以到达的 Mac 地址。

Android 与 iOS 登录页提供「自动查找我的 NAS」：Mac 管理员初始化完成后默认自动启用局域网访问与发现；用户主动关闭后须在 Mac 设置中重新开启。只需保证手机与 Mac 在同一可发现的局域网，搜索约 10 秒后点选设备即可填入地址。默认共用 Mac 的 TCP `16666` 业务端口，Mac 管理端修改后所有客户端与 Bonjour 广播同步使用更新后的端口，**不再为局域网随机分配端口**。Bonjour 仍需独立 mDNS 发现流量，但不属于用户要填写的连接端口。发现结果只接受私有数字 IP 与真实广播的 HTTP/HTTPS 协议，旧版无协议 TXT 时仍按 HTTPS 处理，绝不从端口猜测是否允许降级。选择后不自动登录、也不跳过 HTTPS 指纹校验；未发现仍可手动输入完整地址。真机 Wi-Fi 隔离、mDNS 过滤与部分 Android ROM 仍需实际验收。

默认允许可信局域网的 HTTP，本机 loopback 也允许 HTTP；不强制 HTTPS。用户在 Mac 上手动开启 HTTPS 后，若采用自签名证书，在客户端登录页展开“连接安全设置”，从 Mac 管理端复制并核对 SHA-256 证书指纹；使用系统受信任的 HTTPS 时可以留空。指纹只用于该协议、主机及端口，成功登录后记住；更换服务器不会沿用其他来源的指纹，证书更新后需重新核对。

指纹连接在发送账号、Cookie 和请求内容之前检查证书指纹与有效期，不全局跳过 TLS 校验。图片经同一 API 读取；原生播放器经仅监听本机 loopback、带随机令牌的流式转发访问已校验的 HTTPS，支持 Range 拖动进度，退出即关闭。macOS 沙盒因此增加网络监听权限，监听范围仍由代码限定为 loopback。

登录页不再需要「强制使用 HTTPS」开关：直接使用手动输入或 Bonjour 发现的真实协议，HTTP 与 HTTPS 均可登录；仅允许私有局域网数字 IP 使用 HTTP，公网 HTTP 被拒绝。HTTP 不能加密密码、会话或文件，不应映射到公网；Mac 若手动选择 HTTPS，客户端保留证书指纹校验，不能自动降级。平台允许本地网络连接但客户端仍独立校验地址。
