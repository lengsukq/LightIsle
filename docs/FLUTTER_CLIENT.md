# Flutter 客户端（Android / iOS / macOS）

> 本文对应 `apps/flutter/` 的**当前实现与开发方法**。代码能力不等于真机验收；现状以 [STATUS](STATUS.md)、后续问题以 [ROADMAP](ROADMAP.md) 为准。

## 使用范围与平台差异

| 平台 | 用途 | 重要限制 |
| --- | --- | --- |
| Android | 文件/图库/影视、手动上传、照片前台备份与可选 WorkManager 后台照片任务 | 系统调度、存储权限和 OEM 后台限制必须实测；后台不覆盖视频 |
| iOS | 文件/图库/影视、照片/视频前台上传、RAW/Live Photo 资源处理 | iCloud 未下载原件与系统后台备份无完整自动保障 |
| macOS | 独立的 LightIsle Client，连接已有 NAS；宽屏侧栏 | 不是管理端、不创建 NAS 服务、不执行本机磁盘危险操作 |

**多硬盘**：读取用户的三类存储绑定，按 `rootID + generation` 定位对应盘；管理员逐盘设置成员额度。普通成员新根默认 100 GiB，同盘多分类共用。私人目录尚未实现全写入渠道硬配额（`enforcement=pending`），出错不换盘或绕过授权。

**2026-11-03 默认媒体目录布局**：每个完成身份验证且可写的 NAS 根目录，在首次打开/重新挂载时尝试创建两个真实文件夹：`图库/`（照片、Live Photo、图库短视频）和 `影视/`（电影、剧集视频和字幕等）。已存在的同名目录保持不变；若遇到只读磁盘、同名普通文件或符号链接，不擅自覆盖/更换根目录，保留原盘可访问并记录服务端警告。Flutter 的图库/影视手动上传及其“查看文件”入口默认分别指向这两个目录，且完整保留原件；个人分类绑定仍使用服务端分配的 `Users/uN/photos` / `Users/uN/videos` 路径，不能为了表面一致而绕过个人磁盘配额和 ACL。图库扫描排除顶层 `影视/`，影视扫描排除顶层 `图库/`，目录增量扫描同样过滤。旧文件不会自动移动：原来放在根目录或其他用户目录的照片/电影仍可以被原有扫描流程识别，避免移动导致照片收藏、视频观看进度、分享链接、备份索引及物理盘代际失效。需要集中整理历史文件时应另行提供带权限/冲突/数据校验的显式迁移操作，**不得通过直接复制后删除**。

**2026-11-02 已有 P1 代码入口**：离线照片原件按 NAS 来源/稳定用户/根代际隔离缓存、RAW 扩展格式识别、iOS RAW/Live Photo 资源保存、AirPlay/PiP/DLNA 相关播放器与撤销保护。上述均需要对应设备验收；音乐未开发。

**2026-11-03 存储卷浏览与角色权限**：管理员概览显示 macOS 物理卷容量与文件系统，并精确关联同一卷上已经登记的 LightIsle NAS 存储根；只有根在线且身份代际有效时才可点击“浏览文件”，复用既有 FilePage/API。多个 NAS 根位于同一物理卷时逐一列出。未登记的 exFAT/NTFS 卷提示在 Mac 原生管理端配置，Macintosh HD / Recovery 等系统分区绝不直接开放整个 macOS 文件系统。Go root discovery 只对管理员返回已验证 root 所在的 `volumeMount` 用于显示关联，该字段不是任意文件系统访问权限；成员不会收到挂载路径。普通成员不请求 /system 物理卷列表，仅根据 `/api/v2/me/storage` 的分类 locations 校验 userID、rootID、generation 和相对路径，浏览属于自己且已分配的普通文件/图库/影视目录；离线、未分配或失效绑定不可点击，不在顶部目录菜单列出其他根。硬盘更换或代际变化时清除旧入口，阻止静默切换到默认共享根。后端原有目录 ACL/硬盘配额继续生效，新客户端与 Go Core 同步更新后才能完整关联物理卷与登记目录。

## 产品边界

Flutter 是现有 NAS 的用户客户端。Android、macOS、iOS 共用业务代码，窄屏底部导航，宽屏侧栏，支持系统浅深色、大字体、语义标签与键盘导航。macOS 应用名称为 **LightIsle Client**，使用独立 bundle ID，和已有 SwiftUI **LightIsle.app** 管理端区分。

NAS 仍只运行在 macOS arm64；原生管理端拥有 Go 服务生命周期，负责首任管理员初始化、共享根目录授权、可选的局域网 HTTPS 和本机备份恢复。Flutter 不另启 Go 服务，不增加首次注册或本机特权 HTTP 接口。退出客户端不会停止 NAS；退出原生管理端会停止 NAS。

## 登录状态保留

2026-10-27：默认在本机保留最近一次成功登录的有效会话，关闭、重启客户端后自动恢复。保存服务器来源、证书指纹、会话 Cookie 与服务端到期时间，**不保存密码，也不把会话写入 SharedPreferences、日志或 URL**。iOS/macOS 通过系统 Keychain 保存且关闭同步；Android 通过 Keystore 的独立 AES-GCM 密钥加密后保存，退出时删除密文和对应密钥。未引入新依赖。

启动先经原有 TLS/证书指纹校验，再向 `/api/v2/auth/me` 验证会话并读取当前账号与角色；不会把本机缓存的身份直接当成登录成功。自动连接最多等待 12 秒，其他 API 沿用原有超时。NAS 离线、网络超时或证书错误时保留会话，显示重试及“使用其他账号或服务器”。本机到期或 NAS 返回 401 时清除保存记录并要求重新登录；当前后端会话期限为 30 天，客户端不续长到期时间。

主动退出/切换服务器及修改密码后退出都会清除本机记录。若安全存储暂不可用，会显示解锁设备/检查存储后的重试提示，不伪装为已经保存或清除。Android 验证通过后重新绑定前台会话，保持同账号已有后台备份授权的原有规则；退出、切换账号和失效时会撤销原生后台备份。即使应用被系统杀掉、前台令牌丢失，也可以从原生加密配置清除旧授权、推进 Worker generation 并尽力取消旧任务；仅取消 WorkManager 超时但授权已持久删除时，退出仍可完成。新登录若安全保存之后的原生绑定失败，会回滚该次保存，避免下次重启意外登录；已有登录恢复失败则保留原记录供重试。

验证：登录/重启恢复、来源/指纹/令牌/期限约束、离线重试、服务端撤销、本机过期、离线退出、当前会话失效、保存失败恢复、原生绑定失败回滚、离线切换账号清理旧 Worker、退出清理失败不假报成功，以及持久化/后台会话操作串行化均已纳入 Flutter 测试；本机 Mac 的隔离 Keychain 服务已验证写入、读取、更新与删除。本轮追加复核：`flutter analyze --no-pub` 无问题、`flutter test --no-pub` 197 项通过、1 项跳过，Android arm64 Release APK 构建通过（保留既有 pdfx Kotlin 兼容警告）。Android/iOS 实机重启和设备锁定状态仍需设备验收。

## 移动端布局与手动上传

### NAS 连接测速与稳定性诊断（2026-11-03）

- **入口**：管理员与普通成员均可从 Flutter「设置 → 文件与连接 → 连接测速」进入。采用 LightIsle 原生设计 token：蓝青/淡紫渐变、流畅环形进度仪表、连续延迟曲线、分阶段高亮状态；320px 手机与桌面自适应，高对比/减少动态效果时禁用装饰性动画。
- **真实测量**：使用与文件 API 一致的 Cookie、TLS 证书指纹校验和禁跨域跳转策略，仅访问当前登录 NAS 的 `/api/v2/network-test/ping`、`download`、`upload`。HTTP RTT 采样提供平均/P95 延迟、抖动、失败请求比例；下载/上传分别使用固定大小随机数据，显示 Mbps 和 MB/s。首次请求预热连接，不把建立 TLS 的时间全部误算成稳定延迟。HTTP 请求失败率**不是 IP 层丢包率**，短时间采样**不代表长期在线率**。
- **资源与安全**：Go 端只允许已登录的账户调用，下载由内存中的随机流产生，上传直接读入 `io.Discard`，不创建用户文件、不占用配额、不触碰私人硬盘；请求最大 16 MiB，进程内限同时 2 个传输，启用 `no-store, no-transform` 避免代理缓存/压缩导致虚假测速。快速模式约 8 MiB、完整模式约 32 MiB 传输量；手动启动，随时停止，离开页面释放专属测速连接。透过蜂窝网络/FRP/VPN 访问 NAS 时仍会消耗对应通道的流量。
- **兼容**：需同时升级 Go Core 和 Flutter 客户端；旧 Core 缺少测速路由时提示升级。连接诊断无需管理员权限，且不会暴露物理卷或磁盘目录。需在真实 Android/iOS 上复核 Wi-Fi/热点/远程隧道、弱网、退出和系统锁屏的表现。
- **持续稳定性观察**：新增「持续观察」模式，约一分钟内每 2 秒发送一次轻量 HTTP 请求（不进行上/下行大流量测速）；显示样本成功率、最长连续失败次数、平均/P95 延迟与抖动。认证 Ping 还返回当前 Go Core 进程运行秒数，客户端可以观察是否存在进程重启迹象；该值**不是** Mac 的开机时间，也不能证明历史在线率。检测结果只能描述当前设备到 NAS 的短时可达性，不能等同 ICMP 丢包率。Go 端另增加每登录会话 5 分钟累计 256 MiB 的内存测速流量预算，超出返回 429 和 Retry-After，避免家用 NAS 被频繁测速占满带宽。Flutter 测速上传采用支持背压的流式请求，弱网下容许最多 90 秒传输，防止 UI 同步写大数据造成卡顿。

### 全端交互复核：上传任务、导航、反馈（2026-11-03）

此次横向复核登录/连接、概览、多根存储、文件管理、图库、影视、下载/照片备份、账户安全和设置，以及共同的触摸尺寸、空操作、加载与失败反馈。**主要可复现的问题和对应改动**：

| 发现的反直觉操作 | 调整 |
| --- | --- |
| 临时 FilesPage 退出会取消照片/影片/普通文件上传，切导航就失去队列 | 上传任务归 ClientShell 会话所有；所有上传入口复用原有分块/校验流程，返回与换页不再取消；顶部显示“传输任务”及未完成数 |
| 上传目的盘在进行中被页面切换，存在误用其他 selectedRoot 的风险 | 每个任务固定 rootID+generation 和独立会话 API，不能跟随页面选择重定向 |
| 重启后来源临时 URI 无法读取，反复点“重试”无济于事 | 保留服务端断点记录并按 NAS/账号隔离；缺失来源时显示失败并提供“重新选择原文件”，恢复前重新计算 SHA-256，拒绝相同名称/大小但不同内容的错误续传 |
| 当前文件目录上传完成后不自动显示新文件 | 接收匹配目录与根的完成事件，自动刷新浏览列表 |
| 上传中退出/切换账号未提示未完成任务 | 退出确认展示上传数量并说明中断/重登恢复条件 |
| 恢复历史任务可能阻塞首页的 NAS 连接指示 | 将本地恢复置于独立异步流程，用户无需等待任务数据库/文件选择器回放才能打开概览 |
| 相册详情点击照片没有反应 | 打开既有全屏图库查看器，支持手势，不另造缩放组件 |
| 成员点击存储切换菜单，里面只有不可选项目 | 改为可点击刷新本人存储配置；管理员仍保留可操作的卷选择，触控入口高度至少 44dp |
| 上传报错只显示 FormatException 类名，配额状态使用“开发中”等内部文案 | 使用全端 userFacingError 中文提示；明确说明部分写入通道暂未实施全部硬配额，避免误导 |
| 部分底栏/缩略图状态只有 10–11px | 高频小字提升到约 12px 以上，保留系统文字缩放和窄屏自动隐藏标签 |

**边界**：当前上传中心解决“在应用内离开上传页或切标签”问题；应用被系统暂停、锁屏或杀进程后持续上传**不保证**，现有恢复依赖源文件或重新选择原件。要做到操作系统级后台长期传输，还需 Android Foreground Service/WorkManager 与 iOS background URLSession、持久化读取权限和真机长时间测试；不要把 Dart Timer 当作后台服务。服务端执行的下载与手机客户端上传属于不同执行主体，已保留各自原有逻辑，未来如合并任务视图应复用状态源而非重复实现上传/下载队列。

### 管理员诊断与 WebDAV 本地密码库（2026-11-03）

- **Flutter 管理员专属设备诊断**：设置页新增“设备诊断与 Key 状态”。只读取已有管理员 API，展示最近 180 条处理器/内存/磁盘占用采样、网卡与默认网关、磁盘列表及手动触发的外接磁盘 SMART 检测；SMART 不可用时显示明确的原因，不推断设备健康。天地图和 TMDB 只显示 Core 是否接收到 Key 的配置状态，**不回传 Token、Key、硬盘敏感管理命令**。Mac 钥匙串的 Key 配置与清理、系统服务控制、磁盘挂载/格式化、配置恢复仍由原生管理端负责；不扩展远程写密钥端点。
- **WebDAV 密码可重复查看（限当前设备新保存的凭据）**：Go Core 继续只保留 144 位随机生成密码的 SHA-256 摘要；绝不从数据库恢复旧密码。iOS/macOS 使用独立且不参与 iCloud 同步的 Keychain 项，Android 使用单独的 Keystore AES-GCM 密钥和密文存储。创建或重新生成 WebDAV 凭据时，本机安全保存新密码；点按同一条凭据可以再次查看和复制。缓存按 NAS origin 和稳定账号 ID 隔离，读取前核对服务端由摘要生成的不可逆版本标识；其他设备轮换后，本地旧密码不再显示。存储不可用时仍可手动复制，但不会谎称持久保存。旧凭据或其他设备生成的凭据无法反查，提供明确确认的“重新生成”，立即令旧密码失效，原有凭据 ID 和标签保持不变；撤销则从服务器删除并清理本机缓存。成员也仅能管理自己的 WebDAV 凭据。**不会保存到 SharedPreferences、日志、文件名、URLs 或登录会话记录中**。
- **安全与兼容**：新版本 Core 增加原子轮换接口，以及列表的不可逆凭据版本字段；升级后才可在其他设备密码变更时准确失效本机缓存。移动端旧版仍可生成及撤销凭据；历史密码不会通过升级变得可恢复。业务变更需要新 Core 和新 Flutter 客户端共同部署，iOS/Android/macOS 原生安全存储仍需设备验收。

## 手机原片备份的校验与遗漏

- Android 前台仍受原片 2GiB 上限约束，后台仅备份照片且大于 100MiB 需要前台处理；这些遗漏不计为成功。iOS 原片准备上限为 32GiB，iCloud 尚未落盘的原片不会被自动下载。
- 2GiB 以内继续使用完整 SHA-256 接口。大于 2GiB 的 iOS 原片，在同一次本地读取中产生完整摘要与 4MiB 分块摘要；NAS 逐块读取实际文件，要求全部范围、长度、摘要及文件版本一致，每块前后检查暂停状态。NAS 同时最多进行两次哈希读取，不能把 HEAD 大小相等当成校验成功。
- 大原片分块校验目前只开放给通过已打开文件描述符确认的本机 APFS；其他磁盘格式明确返回 `verification_filesystem_unsupported`。文件版本由物理身份、修改/变更时间、大小等组成，不能把它当作文件系统快照；不承诺在内核磁盘读取阻塞时立即取消。
- 单张原片缺失、iCloud 未落盘或本机原片读取失败，会登记为未完成并继续后续资产；权限撤销、服务/缓存故障、取消、NAS 网络或写入/校验失败仍停止本轮。未解决遗漏存在时不写完整备份时间，扫描到末尾后可从最新照片重新检查重试。
- 每个账号/服务器/设备和照片或视频模式仅保留一份失败集，最多 512 条匿名资产摘要，超出部分保留遗漏数量；图库版本改变或重新全扫会重建该集合。失败记录持久化失败时不得继续推进页游标。手机原件始终保留，真实大视频、退后台和外接盘仍需设备验收。

## 连接

1. 打开现有 `LightIsle.app`，完成管理员初始化；局域网 HTTP 会默认自动开启，必要时可在 Mac 设置中切换 HTTPS 或关闭访问。
2. Flutter 输入 Mac 显示的服务地址和已有账号。
3. macOS 本机可用 `http://127.0.0.1:16666`；手机需要使用可以到达的 Mac 地址。

Android 与 iOS 登录页提供「自动查找我的 NAS」：Mac 管理员初始化完成后默认自动启用局域网访问与发现；用户主动关闭后须在 Mac 设置中重新开启。只需保证手机与 Mac 在同一可发现的局域网，搜索约 10 秒后点选设备即可填入地址。默认共用 Mac 的 TCP `16666` 业务端口，Mac 管理端修改后所有客户端与 Bonjour 广播同步使用更新后的端口，**不再为局域网随机分配端口**。Bonjour 仍需独立 mDNS 发现流量，但不属于用户要填写的连接端口。发现结果只接受私有数字 IP 与真实广播的 HTTP/HTTPS 协议，旧版无协议 TXT 时仍按 HTTPS 处理，绝不从端口猜测是否允许降级。选择后不自动登录、也不跳过 HTTPS 指纹校验；未发现仍可手动输入完整地址。真机 Wi-Fi 隔离、mDNS 过滤与部分 Android ROM 仍需实际验收。

默认允许可信局域网的 HTTP，本机 loopback 也允许 HTTP；不强制 HTTPS。用户在 Mac 上手动开启 HTTPS 后，若采用自签名证书，在客户端登录页展开“连接安全设置”，从 Mac 管理端复制并核对 SHA-256 证书指纹；使用系统受信任的 HTTPS 时可以留空。指纹只用于该协议、主机及端口，成功登录后记住；更换服务器不会沿用其他来源的指纹，证书更新后需重新核对。

指纹连接在发送账号、Cookie 和请求内容之前检查证书指纹与有效期，不全局跳过 TLS 校验。图片经同一 API 读取；原生播放器经仅监听本机 loopback、带随机令牌的流式转发访问已校验的 HTTPS，支持 Range 拖动进度，退出即关闭。macOS 沙盒因此增加网络监听权限，监听范围仍由代码限定为 loopback。

登录页不再需要「强制使用 HTTPS」开关：直接使用手动输入或 Bonjour 发现的真实协议，HTTP 与 HTTPS 均可登录；仅允许私有局域网数字 IP 使用 HTTP，公网 HTTP 被拒绝。HTTP 不能加密密码、会话或文件，不应映射到公网；Mac 若手动选择 HTTPS，客户端保留证书指纹校验，不能自动降级。平台允许本地网络连接但客户端仍独立校验地址。
