# 性能预算与基准测试

> 这里列的是**目标值与测量方法，不是已验证的实际占用**。必须在 Apple Silicon Mac 上实测整套进程的资源基线。LightIsle 是 SwiftUI Mac 管理端 + 内置 Go Core、独立浏览器中的 Web 与可选 Flutter 用户端；关闭窗口仍在菜单栏运行 NAS，明确退出 App 才停止 Core。UI 视觉效果不能以持续耗电或高内存为代价。

已实施的按需 aria2、闲置根服务释放、Mac 隐藏窗口低频采样、缩略图索引上限与 Web 原图惰性加载，以及资源泄漏修复和回归证据，见 [内存占用审查及优化清单](MEMORY_OPTIMIZATION_REVIEW.md)。实机完整前后对比与长期曲线仍待验收，不宣称已达到资源预算。

### 2026-10-27 短时空库检查

Apple M4 Pro / darwin arm64、本地 Go 1.26.1 普通构建，独立临时数据目录、无媒体/成员/下载负载，仅回环 health 请求；本机 aria2 已安装。Core 启动后 0/30/60 秒 RSS 分别为 **21,040 / 21,536 / 21,760 KiB**，三次均无 aria2 或媒体子进程；关闭父进程输入后 Core 正常退出（退出码 0）。临时目录随后清理。

该样本只验证本轮按需进程行为与短时健康检查。它没有优化前对照、完整 SwiftUI/浏览器进程、10 分钟稳态、实际图库、独占脏页或长期增长趋势；**不能据此宣称优化了多少 MB、没有其他内存泄漏或已经达到下面的预算**。合成缩略图索引分配基准另见内存优化记录，不混入 RSS。

## 1. 资源预算（目标）

| 状态 / 模块 | 初始目标 | 测量口径 |
| --- | --- | --- |
| Go Core 空闲 | 常驻 RSS 50–120 MiB | 启动稳定 10 分钟后进程 RSS |
| SQLite + 小型常驻索引缓存 | 约 10–40 MiB 额外内存预算 | 避免与 Go Core RSS 重复计算 |
| Go 核心 NAS **空闲后台合计** | 力争 100–250 MiB | Go Core + 实际驻留的 LightIsle 媒体进程，**不包含 SwiftUI App、独立 Web 浏览器或 Flutter 客户端** |
| **整套 NAS 宿主空闲总计** | 真机实测后制定基线，不预先承诺 | SwiftUI Mac App + Go Core + 本项目媒体子进程；浏览器与 Flutter 单列，避免混入或遗漏 |
| 空闲 CPU | 在无事件/任务时接近 0，目标平均 <1% 单逻辑核 | 长时间采样并标记单位 |
| 非媒体 API 响应 | 优先 p95 <100ms（局域网、热缓存） | 真机固定样本与负载，记录方法 |
| 图片索引并发 | 初始限 1–2 worker，可配置 | 控制峰值内存与 CPU |
| 视频转码并发 | 开发实现的会话管理器默认最多 2 路（实际随版本核实） | 限制 CPU、内存、磁盘临时缓存；测量硬件解码和软件回退峰值 |
| 缩略图磁盘缓存 | 默认 1 GiB，可在 Mac 管理端调整为 256 MiB–8 GiB，另设每根 50,000 条索引上限 | 可清理重建、保留近期使用；不要把全部缓存算作常驻 RSS |

**以上数字均须实测确认。** 系统级 RSS 与 Swift/FFmpeg 子进程 RSS 的统计应明确且不能遗漏；内存计算避免同一份共享内存重复累加。

不要将 Go 后台资源预算误写为完整的 Mac App 资源预算。**Mac 管理端不内嵌 WKWebView**；用户打开独立浏览器或 Flutter 客户端时单独测量其资源。关闭主窗口后 API 应继续运行；只有明确退出 App 才要求本项目 Core 和监听端口全部释放。

## 2. 必须坚持的性能机制

1. **单 Go 主进程**：认证、文件、图库、影视、任务索引公用服务和 SQLite。
2. **按需媒体处理**：Swift Worker/FFmpeg 有空闲关闭策略，不强制常驻耗资源模型。
3. **批处理 + 增量索引**：FSEvents 为触发，后台定期纠偏；卷离线不全量触发删除。
4. **有界队列**：限定 goroutine / 媒体 worker / 扫描速率 / SQLite 写事务时长。
5. **文件流式 I/O**：下载使用 Range，上传分块校验；不一次读入整部影片或大文件。
6. **响应式页面优化**：照片、文件列表 cursor 分页、虚拟滚动、按需尺寸缩略图。
7. **睡眠友好**：无任务时关闭无意义轮询，硬件监控频率适中，可配置。
8. **缓存独立**：用户业务数据与可删除的缩略图、转码缓存分离，磁盘空间受控。
9. **克制的 iOS 27 风格**：只在导航与重要操作层使用 Liquid Glass；图像网格/文件表格使用不透明或标准材料；Web 限制 backdrop-filter 的面积，减少透明或降低性能时使用不透明回退。
10. **应用生命周期**：只有用户打开 LightIsle.app 时 Go 后端才存活，完全退出后的残留 Go/媒体进程属于性能与功能缺陷。

**Web 按需加载的现有实现（2026-10-25）**：图库与影院组件由 `App.vue` 按需导入，`CinemaView.vue` 在浏览器确实需要 HLS.js 时再动态导入播放器。重构期间主 JavaScript 构建产物由约 904 kB 缩至约 227 kB（不同代码基线及构建环境的静态文件体积比较，**不等于冷启动用时减少相同比例**）。独立 `hls.js` 资源约 593 kB，仍触发 Vite 的 500 kB 分块体积警告，但不阻塞首页；真实网络缓存、首次播放启动时长、内存和 Safari/Android 解码性能仍应实测。

## 3. 性能测试矩阵

| 测试 | 样本及方法 | 观察值 |
| --- | --- | --- |
| 冷启动 | 双击 LightIsle.app 启动 Go Core 且不启动 Colima | Mac 原生首屏、服务就绪时间、各进程 RSS、失败率 |
| 7×24 空闲 | 72 小时不执行媒体工作 | CPU 均值/峰值、RSS 趋势、任务泄漏 |

## 4. 质量红线

- 禁止同步全盘扫描阻塞登录和系统 API。
- 禁止 API 接收用户请求后无限制启动 FFmpeg/媒体进程。
- 禁止无限增长的缩略图/转码缓存、任务表和日志。
- 禁止将完整照片/视频载入内存实现简单拷贝。
- 非必要不自动启动 Colima / Docker VM。
- 任何需要常驻 AI 模型的功能必须可单独禁用或不安装。
- 大面积连续毛玻璃、粒子/反光特效不得造成长期 CPU/GPU 负担；低性能/无障碍模式必须关闭动态材质。
- 完全退出 App 后，不允许保留 LightIsle 自有的 NAS HTTP API 及后台工作进程。
