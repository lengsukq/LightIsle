# 存储设置、外置磁盘与离线恢复

> **2026-11-02 已按现有 Go Core 账本、Web/Flutter 策略核对。** 这里只描述现行代码和真实风险；物理多盘功能仍为 Beta 开发预览。

## 每硬盘独立额度

成员按 `user_id + root_id + root_generation` 独立配置，每个新根默认 **100 GiB**；同一个根上的 `files / photos / videos` 三类文件只共享该根的额度。A、B 盘各有 100 GiB 时，A 盘的写入不扣减 B 盘的额度。管理员不受应用逻辑额度限制，但仍受磁盘实际空间限制。

- SQLite `user_storage_root_quotas` 持久化单盘额度；旧 `user_storage_quotas` 仅为历史迁移来源。`storage_quota_migrations/per_disk_v1` 保证旧额度只在首次升级时分配给已绑定或已有账本的根，保留原文件及未解决预占；之后新盘使用默认 100 GiB。
- 管理员使用 `PUT /api/v2/users/{id}/storage/roots/{rootID}/quota` 逐盘设置额度；旧总额写入 `PUT /api/v2/users/{id}/storage/quota` 返回 **409**。`GET /api/v2/me/storage` 的 `rootQuotas` 是逐盘额度与账本数据；旧顶层 `quotaBytes:null` **不表示普通成员无限额**。
- `accountedBytes` 与 `reservedBytes` 只反映已纳入账本的使用/预占；离线旧根仍保留账本。`GET /api/v2/roots` 的文件系统容量来自物理卷，同一 APFS 卷多个根的可用空间不可相加。
- **`enforcement=pending` / `usageComplete=false`**：应用内部分写入已有额度保护，但无法把配额设置称为所有通道都生效的硬配额，更不是 macOS 对 Finder/终端直接写盘的系统配额。

## 当前写入边界

| 通道 | 代码处理 | 结果 |
| --- | --- | --- |
| 根限定的普通/分片上传、个人相册上传 | 写入前按目标根代际做 SQLite 额度预占，发布后计入用量 | 部分执行 |
| 同根、同一所有者已入账的普通文件复制/移动/重命名 | 受限冲突处理、目标预占与账本更新；不盲目覆盖 | 部分执行 |
| 移入回收站与永久清理 | 回收站继续计入额度，确认清除后才能释放账本 | 部分执行 |
| WebDAV、下载发布到私人 `Users/` 目录 | 未接入全渠道账本前拒绝私人目录写入 | 安全拒绝，而非已完成配额 |
| 私人目录跨根迁移、递归拷贝、Finder 直接写文件 | 不承诺统一应用账本事务 | 未完成 |

**不得用放开旧 WebDAV 或下载路径代替计费。** 新增通道必须锁定根身份，预占真实目标字节，处理崩溃后恢复与未知状态；人工用量核对不能直接清空账本。外部进程有权限直接写盘时，HTTP 限额不能替代 macOS 级文件系统控制。

**2026-11-04 代码增强（不等同实盘验收）：** 根限定普通上传、分片完成与已计费复制，在已验证的物理根发布文件后、SQLite 预占转已使用前，再次核对当前根租约；掉盘或同名目录替换后保留可能已发布的文件与不确定预占，不返回成功。未计费的共享普通上传和复制同样在返回前核对根身份并拒绝将离线旧卷报告为当前 NAS。对应故障注入在临时目录中模拟旧目录重命名并原址新建同名目录，不能代替 USB 物理断电、电源抖动、APFS/exFAT 实盘测试。

## 私人目录与自动寻址

- Web/Flutter 按用户绑定，将 `files`、`photos`、`videos` 指向不同登记物理根；目录为 `Users/u<数字用户ID>/<类别>`，不是用户自填任意路径。
- 访问时检查 `rootID + generation`、在线状态与成员权限。离线或换盘不默默写到另一根。Android/iOS 照片前台备份走根限定 v2；Android WorkManager 后台照片任务已有代码，但必须在真实系统调度下验收。
- Web 将切盘请求取消和代际管理集中到 `rootContextLifecycle.ts`，由 `chooseDiscoveredRoot` 纯函数决策是否恢复之前选中的根。刷新列表后，**显式选中的物理根若已消失，不再暗中切到默认共享盘**：中断旧请求、暂停原上传并显示该根不可用，要求用户重新连接或明确选择另一根。仅首次无选择时可考虑恢复会话保存的根；硬盘代际变化则强制重新绑定。
- 管理员可在 Mac 移除原物理根登记，再从 Web/Flutter 确认放弃对应分类旧绑定并重建空白目录。**解除登记不删除旧盘文件，不自动拷贝或迁移**；旧预占不得因离线自动当作零。
- API 唯一版本为 `/api/v2/...` 与 `/api/v2/roots/{rootID}/...`；历史 v1 客户端不再支持。

## 存储的正确用法

- Mac「数据与存储 → NAS 存储空间」通过 RootRegistry 登记、重连或移除专用文件夹。将**已登记且在线的 rootID**设为默认根；不会自动移动、合并原文件或复制旧成员授权。默认根持久化于 `shared-roots.json` 的 `defaultRootID`，必须验证磁盘和目录身份，移除默认根后不自动选择另一块盘。
- **一键切换目录**：Mac 原生「选择文件夹并切换」支持选择任意合规的现有专用目录。已登记目录直接设置默认根（复用原 rootID），未登记目录原位登记后设为默认；既不要求预先「添加」，也不移动旧文件或自动继承 ACL。不同目录永远是不同根 ID。两个动作不能部分地偷偷重用旧 rootID。
- **旧数据迁移（显式复制）**：Mac 原生界面选**来源注册根 + 目标注册根**，先通过物理根租约预览文件数、字节量、冲突数和目标可用空间，再由所有者确认启动。Core 异步复制、可查进度和取消；使用源/目标 rootID + generation + 租约，目标基于已验证的句柄进行原子 no-replace 发布，已存在文件不覆盖，源文件不删除。失败/断电后保留已复制的文件；重新预览并运行时只补充缺失文件。
- **迁移暂不自动处理的敏感数据**：`Users/` 私人目录（需要账户授权和配额账本衔接）、图库相册/收藏、影院观看记录、应用配置数据库及旧公开分享授权。它们不会被当作普通目录合并，也不会自动授予目标根的成员权限。源盘必须保持可访问，待后续专门的账户级迁移能力确认后才能处理这些数据。内部 `.lightisle-*` 文件、符号链接和其他不支持的条目跳过。
- 原 `SharedFiles` 目录在**首次且 RootRegistry 尚无配置**时尝试原位登记为物理根；只在迁移期间临时打开旧存储配置然后关闭，不作为运行中的第二个共享根。旧 `share set/forget` 指令统一拒绝，正常 Mac 存储操作仅使用 `roots add/rebind/set-default/remove`。原文件、原授权记录不会自动搬迁/授权；已主动删除所有登记根的配置不会在重启时被再次导入。
- 默认 `/api/v2/files`、`/photos`、`/cinema` 等文件和媒体入口转发到 RootRegistry 选定根的身份/代际服务；明确指定根仍通过 `/api/v2/roots/{rootID}/...`。无默认根直接拒绝，不转向本机任意其他路径。
- WebDAV `/dav/` 使用 RootRegistry 默认根的物理租约和 rootID 成员授权，每次读写仍会检查授权与原始目录身份；**不再接受旧路径授权作为新根授权**。现阶段 `Users/` 私人目录在 DAV 中继续拒绝访问（须补齐全渠道硬配额后才能开放），其他授权目录可正常使用。
- aria2 下载中心通过 RootRegistry 创建、检验和发布任务，并在 SQLite 中持久保存 `root_id + root_generation + root_binding`；物理根切换、重新登记或失联会拒绝自动发布。旧下载任务保留历史/暂存文件，但缺失 `rootID` 的任务标记 `download_root_unbound`，由所有者主动重新创建、按需核对恢复，绝不静默继承新盘写入权。下载到 `Users/` 同样暂时拒绝，避免绕过个人配额。
- 原生目录导出、容量告警、配置备份和 TMDB 索引按 RootRegistry 身份运行；Mac 应用监听已登记在线根的文件变更，附加根通知还带代次并合并目录。旧版轻屿回收站的自动永久清理已暂停，已有文件可查看和恢复；系统废纸篓接入尚未完成。
- **系统废纸篓安全验证仍需完成**：本机合成临时文件测试中，先取得 macOS 文件引用、再将原文件移走并在原路径创建同名文件时，`FileManager.trashItem` 实际移走了同名新文件。不能仅凭该引用解决路径替换竞争；需要可靠地固定实际对象并验证 Finder 恢复、外置盘和 WebDAV 覆盖行为。测试只使用临时文件，并非真实外置盘验收。
- 上传暂存默认保留 30 天；管理员可设置 0–3650 天（0 关闭自动清理）。后台按在线根分批检查，只有未发布、状态可靠且记录与暂存文件均超过保留期的项目才清理；根身份不匹配、目标出现、记录异常或预占释放失败时保留待核对状态。尚未覆盖缩略图和历史记录的统一 Web 规则配置。
- Web 和 Flutter 的文件管理、图库、影院均使用带授权校验的原文件回收站接口。图库与影院单项或多选最多 50 项；删除前确认，切根/页面数据变化阻止继续操作。回收站中保留原件，恢复和永久清理仍经文件管理授权入口。
- RootRegistry 是**生产运行时唯一根管理入口**，新根各有 rootID / generation、权限、媒体库和任务。重新绑定同一物理目录需验证身份；更换硬盘或 inode 需要新建 rootID、重新授权。已取消逐根文件备份、历史单根数据迁移与自动跨盘恢复；现阶段仍需全渠道配额及真实硬盘验收。
- 图库和影视索引按 rootID 与 generation 隔离；缺失或身份无法确认的记录保留供目录所有者检查，不按同名新文件自动继承资料。旧代次资料的完整检查和处理入口仍待补齐；不会自动删除或迁移这些记录。

## 外置磁盘基础管理（统一 Core）

| 操作/信息 | 已有设计 | 安全边界 |
| --- | --- | --- |
| 列出设备、卷格式、容量、是否只读、挂载状态 | `core/internal/diskmgmt`，Web 管理员 `GET /api/v2/admin/disks`，Mac 原生私有 `disk list` | 系统卷、内部盘与未知设备标识只读展示 |
| 修改卷名、挂载、安全弹出 | Web 管理员 `POST /api/v2/admin/disks/actions`；Mac 私有 `disk action` | 执行前**重新验证**卷身份、是否外置、挂载及忙碌状态；无强制弹出、无任意 shell、无后台提权 |
| 盘容量/读写速率 | `statfs` / 系统指标与 IOKit 只读计数 | 计算不正确或首次采样必须显示未知/无数据，不能编造速度 |
| SMART 状态和温度 | diskutil 基础状态、可选 smartctl 原始结果、Web 管理员查询及 Mac 用户主动授权 | 未装工具、USB 桥接不支持或没有读盘权限时显示**未知**，不能叫健康；历史仅在按需采集时入 SQLite，按身份隔离、30天/360条上限 |

对当前及离线 NAS 共享根、备份目的地和正在运行的任务所用磁盘，Core 阻断风险操作；不允许用户通过 HTTP 自由指定设备路径。Mac/管理员 Web 复用同一个 Core，不分别写两套 diskutil 命令。

## 已授权外置盘离线

1. 默认**保留原磁盘身份和所有记录**，提示接回并在重连时再次验证真实目录/卷；同名替换盘绝不能自动接管。
2. 用户也可在 Mac 明确选择「解除离线盘绑定并清理媒体记录」，但只有原盘确实离线、符合保护条件且二次确认后才允许。该操作可能清理原兼容目录对应的本地图库/影视索引、收藏、相册、观看进度、成员授权和旧分享；原盘真实文件仍完整保留。操作前应独立备份应用数据。
3. 清理存在跨 SQLite/配置持久化失败的局部状态风险，系统必须提示重启和手工核对，不能谎称是文件+数据库原子事务。
4. 重新接入原卷时，单根 FSEvents 和额外根周期调和分别扫描，补回脱机时的媒体变更；这只更新**索引**，不会自动备份原片。

## NTFS、格式化与选择文件系统

- macOS 默认通常不能写入 NTFS，界面应解释只读原因，不将它与磁盘损坏/SMART 状态混淆。
- “格式化为 Mac 可写磁盘”**只是打开 macOS 系统磁盘工具**。由用户本人确认物理设备与数据丢失风险，并选择 **APFS**（Mac 专用）或 **exFAT**（跨 Windows/Mac）。LightIsle 不自动运行 `diskutil eraseDisk`、不绕过系统确认，不在测试期间抹真实盘。
- “重命名、弹出、格式化、清理旧元数据”是不同风险动作，不得在界面上混成一个快捷按钮。

## 用户可执行的安全检查

先在 Mac 确认当前共享位置确实是预期硬盘，再检查只读原因、容量和备份位置。所有实际写入/弹出/重新绑定测试只能用可清空的独立测试盘；断盘、同名替换、跨卷传输、系统休眠、满盘与多用户并发必须逐项验收。可在无真实盘时运行 `go test ./core/internal/diskmgmt ./core/internal/roots ./core/internal/server` 与 `bash scripts/verify-macos.sh` 做代码级回归，**不能替代设备验收**。
