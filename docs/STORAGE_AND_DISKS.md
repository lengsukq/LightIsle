# 存储设置、外置磁盘和离线恢复

> **2026-10-27 全局接口升级（最新）**：后端和 Web/Flutter 已统一为 `/api/v2/...`，旧 `/api/v1/...` 已从 Go Core 的实际路由注册删除，不再支持旧客户端及双版本过渡。管理员系统与账号操作使用全局 v2 URL；指定物理硬盘的数据操作使用 `/api/v2/roots/{rootID}/...`，代际校验、管理员/成员授权及共享目录私人空间防绕过继续生效。旧单根和新多根在本文指**存储范围**，不代表继续保留 v1 HTTP。未解决的全渠道存储计费、iOS 后台执行和真实外接盘验收仍需单独处理。下方先前有关 v1 待清理的记录属于历史。

> **2026-10-27 照片备份修订**：Android/iOS 前台通过同一个 Flutter 备份页调用指定物理照片盘的 v2 API，要求 `Users/uID/photos` 绑定；Android WorkManager 后台使用 Kotlin 原生调度，但上传请求同样为根限定 v2 API 并带代际校验，凭据和硬盘身份由 Android Keystore 加密保护。升级前的 v1 `PhonePhotos` 后台配置失效，需用户在图库重新开启。失联盘会等待恢复，换盘/撤绑定需用户确认重建；不自动迁移旧照片。iOS 后台相册任务和 macOS 手机相册后台备份未实现。完整清除服务端 v1 API 属于独立的全项目迁移工作，不能在保留其他 v1 客户端时直接删路由。

## 个人空间自动路由与容量（2026-10-27 开发预览）

- 在 Web/Flutter「存储空间」里为账号配置三类目录：文件 (`files`)、照片 (`photos`)、视频 (`videos`)；每类可放不同的已登记硬盘，存放位置固定为 `Users/u<用户数字ID>/<类别>`，无需输入自由路径。旧单根模式和未分配类别仍可继续使用默认共享目录，不自动迁移任何既有数据。
- Web/Flutter 打开「文件」「图库」「影院」会读取当前账号类别绑定，核对 rootID、generation、在线状态再自动选盘。Flutter 文件搜索和面包屑以专属目录为起点；访问权限始终由 Core 校验。手动切根仍可操作共享目录。断盘、移除或代际更换时阻断自动寻址，提示连接原盘或由管理员确认重建，不写其他硬盘。
- 手机前台相册备份从 Flutter 图库进入，个人照片绑定时写 `Users/uID/photos/<设备目录>`，并保留哈希校验。原 Android 后台 WorkManager 只理解旧版 v1 `PhonePhotos`；登录时发现个人照片分类绑定，会主动停用旧后台任务，而非误写默认硬盘。多根 Android 后台备份仍待实现。
- **一人一份额度**：管理员不限制应用额度，普通成员默认 100 GiB，可由管理员修改；v2 受支持的普通上传/分片上传、受限复制/移动共用 SQLite `used + reserved` 跨根账本。未纳入计费的私人目录写入渠道（如旧 WebDAV/下载）保持拒绝，目录级或跨根移动也不冒险开放；服务端仍返回 `enforcement=pending`，不宣称全路径硬配额已完成。
- 管理员 Web/Flutter 可点击「核对在线文件占用」，只读取当前 rootID+generation 下已分配的私人目录并逐文件累加，不会写入账本/更改配额/删除数据。扫描值**不包含回收站和待确认写入预占**，不能与账本直接当作相同口径比较；离线、换盘、扫描不完整均明确报告，不能据扫描值清账。大型目录按需手动执行，不启用后台持续全盘巡检。
- 仍需实盘断电、换盘、容量不足、同账户跨盘并发、Android/iOS 照片备份和真实前台/后台切换验证，**此版本不能当作生产验证完成**。

> 整合原 `STORAGE_CONFIGURATION_BETA_PLAN`、`DRIVE_MANAGEMENT_BETA_PLAN` 与 `OFFLINE_DRIVE_AND_FORMATTING_PLAN`。本文只描述现有代码的安全设计及仍需验收的行为，不代表已在真实存储卷执行操作。正式发行还必须满足 [PRODUCTION_RELEASE](PRODUCTION_RELEASE.md)。

## 存储的正确用法

- Mac「数据与存储 → 当前 NAS 存储位置」展示当前完整路径、所属磁盘、空间与在线状态；外置盘卡片可以打开系统文件选择器，在已挂载、可写的外置卷中新建或选择 **LightIsle 专用文件夹**。不要不经确认共享整盘；不在用户不知情时移动旧文件。
- 对于原兼容单根，只有 Core `share set` 的目录身份验证成功后才切换显示。路径前缀不能把相邻磁盘名认成同一卷；挂载失联、符号链接逃逸、备份/传输任务冲突时拒绝或明确提示结果不确定。
- 旧原片、回收站、相册、账户和快照不因选择新目录而自动迁移。不同物理根或旧身份无法确认时，Core 先在账号数据库事务中撤销旧单根目录授权和分享，再保存/发布新根；同一物理目录重连保留授权。保留最近 8 次非秘密授权说明归档，不保存旧链接令牌摘要/密码校验值，不让归档恢复访问权。归档失败时不撤权；撤权后换根失败或配置落盘不确定，Mac 必须分别提示。
- 默认共享目录 v2 API/WebDAV 的认证及处理过程、图库/影视扫描和应用配置备份与切换共用门禁；有活动请求/任务时快速拒绝并提示稍后重试，进入切换锁后再检查后台活动，避免先检查空闲再启动任务的窗口。
- 多根 v2 是**隔离的开发预览**，新根各有 rootID / generation、权限、媒体库和任务。重新绑定同一物理目录可恢复；更换成另一块硬盘或新 inode 时必须新建 rootID、重新授予成员权限，不能继承旧目录成员可见性。逐根计划已开发，正式迁移及单根元数据恢复没闭环前不要开放给普通用户。
- **尚缺的来源隔离**：旧图库/影视关联仍按共享路径保存，同路径更换物理盘后重扫可能复用旧资产/影片 ID 及其相册、收藏、观看记录。撤销文件授权不能替代这项数据迁移；需要先绑定来源物理身份、保留旧记录并让所有者确认映射，不能按路径自动继承。本轮未自动删除或迁移这些记录。

## 外置磁盘基础管理（统一 Core）

| 操作/信息 | 已有设计 | 安全边界 |
| --- | --- | --- |
| 列出设备、卷格式、容量、是否只读、挂载状态 | `core/internal/diskmgmt`，Web 管理员 `GET /api/v2/admin/disks`，Mac 原生私有 `disk list` | 系统卷、内部盘与未知设备标识只读展示 |
| 修改卷名、挂载、安全弹出 | Web 管理员 `POST /api/v2/admin/disks/actions`；Mac 私有 `disk action` | 执行前**重新验证**卷身份、是否外置、挂载及忙碌状态；无强制弹出、无任意 shell、无后台提权 |
| 盘容量/读写速率 | `statfs` / 系统指标与 IOKit 只读计数 | 计算不正确或首次采样必须显示未知/无数据，不能编造速度 |
| SMART 状态和温度 | diskutil 基础状态、可选 smartctl 原始结果、Web 管理员查询及 Mac 用户主动授权 | 未装工具、USB 桥接不支持或没有读盘权限时显示**未知**，不能叫健康；历史仅在按需采集时入 SQLite，按身份隔离、30天/360条上限 |

对当前及离线 NAS 共享根、备份目的地和正在运行的任务所用磁盘，Core 阻断风险操作；不允许用户通过 HTTP 自由指定设备路径。Mac/管理员 Web 复用同一个 Core，不分别写两套 diskutil 命令。

## 已授权外置盘离线

1. 默认**保留原磁盘身份和所有记录**，提示接回并在重连时再次验证真实目录/卷；同名替换盘绝不能自动接管。
2. 用户也可在 Mac 明确选择「解除离线盘绑定并清理媒体记录」，但只有原盘确实离线、符合保护条件且二次确认后才允许。该操作可能清理原兼容目录对应的本地图库/影视索引、收藏、相册、观看进度、成员授权和旧分享；原盘真实文件仍完整保留。操作前应独立备份应用数据。
3. 清理存在跨 SQLite/配置持久化失败的局部状态风险，系统必须提示重启和手工核对，不能谎称是文件+数据库原子事务。
4. 重新接入原卷时，单根 FSEvents 和额外根周期调和分别扫描，补回脱机时的媒体变更；这只更新**索引**，不会自动备份原片。

## NTFS、格式化与选择文件系统

- macOS 默认通常不能写入 NTFS，界面应解释只读原因，不将它与磁盘损坏/SMART 状态混淆。
- “格式化为 Mac 可写磁盘”**只是打开 macOS 系统磁盘工具**。由用户本人确认物理设备与数据丢失风险，并选择 **APFS**（Mac 专用）或 **exFAT**（跨 Windows/Mac）。LightIsle 不自动运行 `diskutil eraseDisk`、不绕过系统确认，不在测试期间抹真实盘。
- “重命名、弹出、格式化、清理旧元数据”是不同风险动作，不得在界面上混成一个快捷按钮。

## 用户可执行的安全检查

先在 Mac 确认当前共享位置确实是预期硬盘，再检查只读原因、容量和备份位置。所有实际写入/弹出/重新绑定测试只能用可清空的独立测试盘；断盘、同名替换、跨卷传输、系统休眠、满盘与多用户并发必须逐项验收。可在无真实盘时运行 `go test ./core/internal/diskmgmt ./core/internal/roots ./core/internal/server` 与 `bash scripts/verify-macos.sh` 做代码级回归，**不能替代设备验收**。
