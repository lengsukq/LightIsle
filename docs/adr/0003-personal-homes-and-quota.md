# ADR 0003：个人空间、分类存储位置与按盘独立配额

日期：2026-10-26。状态：**以全新安装/新账号为目标，分阶段实施；不得把配额设置称作已生效的写入限额。**

**2026-11-02 修订（优先于历史进度段落）**：不再设置跨盘总额度。成员在每个已绑定根代际拥有独立额度，默认 100 GiB，文件/照片/视频在同一根上只共享一份额度，管理员不限应用额度。SQLite 使用 `user_storage_root_quotas(user_id,root_id,root_generation,quota_bytes)`；管理员逐盘调整接口为 `PUT /api/v2/users/{id}/storage/roots/{rootID}/quota`。原账号旧总额度仅首次迁移为升级时每个旧根的初始额度，旧文件和上传预占不删除，新增盘默认 100 GiB。旧顶层 `quotaBytes:null` 不代表成员不限额，客户端应读取 `rootQuotas`。尚未接入配额账本的私人写入继续拒绝，`enforcement=pending` 不变。

## 产品约定

LightIsle 的 RootRegistry 负责**物理共享根**（可以是不同硬盘上的专用文件夹）；本 ADR 在其上叠加**用户私有空间**。一个物理根可以容纳多个用户，每个用户可以把不同类别的内容放到不同根。用户看到的是“我的文件 / 我的照片 / 我的视频”，不应被迫先理解 rootID。

- 每个账号（含管理员）具有固定的逻辑存储位置。类别为 `files`、`photos`、`videos`；下载归入文件类别，不额外赠送一套容量。照片、视频、普通文件可分别指向不同根，同一用户的多个类别也可在同一硬盘。
- **目前按全新安装交付**：管理员先在 Mac 登记多根硬盘，再在 Web 中选择默认根创建账号；Web 在创建成功后为新用户自动请求 files/photos/videos 三个目录的创建与授权。管理员仍可单独给自己分配目录，照片、视频也可按类别单独指定盘。若创建账号时尚未选择在线根，账号仍可创建，需在存储面板手动分配。
- 配置使用 `(user_id, category, rootID, rootGeneration, relativePath)`；相对目录由系统生成 `Users/u{userID}/{category}`，以不可变数字 ID 而非可重命名用户名命名。路径必须先由物理根租约确认，RootRegistry 永不通过路径猜测替换磁盘身份。
- 管理员应用额度不限制，但仍受硬盘实际可用空间约束；成员每个绑定根默认 **100 GiB = 107374182400 字节**，管理员逐盘调整。
- 同一用户同一根的文件、照片、视频共享一份额度；不同根额度独立，互不扣减。跨盘已用和预占的合计仅作库存信息，不用来阻止另一盘写入。
- 用户默认只访问自己的目录，额外共享依然走现有授权模型；管理员作为维护者有权管理所有用户。根授权 `.` 不能作为私有用户目录的数据泄露捷径；必须继续审查通过根级媒体索引、仅 v2 的根 API 与 WebDAV 访问私人目录的边界。

## 用量与写入计费

个人版优先按文件逻辑大小（字节）统计，不实现块级去重、存储池或跨硬盘物理配额。

1. 原始文件计入所属用户配额；缩略图、转码缓存和 SQLite 元数据不计。**回收站仍计入**直到真正清除，避免利用删除/恢复绕过额度。跨盘同一用户“移动”只计一次（复制过程中仍须单独检查真实空闲空间）。
2. 开始上传时按声明总大小预占，服务端在同一 SQLite 数据库事务中核验**目标根额度**。直接 PUT、分块上传、Android/iOS 照片备份、WebDAV、下载中心发布、文件复制及恢复等所有写入路径必须共用同一配额预占/提交/释放机制；不能只拦截浏览器上传。
3. 同账号同根的并发上传不能绕过该盘额度。异常或介质离线时不自动清空账本、也不盲目释放不确定的上传预占；有问题时提示管理员自行检查。容量无法验证时应**拒绝新增超额风险写入**，不能误称还有 100 GiB。家庭版不开发企业级周期实盘扫描修复器。
4. 管理员向成员目录写文件时，应计入**目录所有者**的配额，而不是利用管理员无限额度绕过。缩小额度到低于已用时只禁止新的增量写入，不自动删除文件。
5. 如果目标根离线，本类别写入失败并提示检查连接，不偷偷转写到另一个盘。家庭版**不做自动跨盘迁移**：确认旧空间不用后，管理员在 Mac 上移除硬盘登记，回到 Web 解除对应账号的分类绑定，再选择新盘创建空白目录；原盘原件不被格式化或删除。

## 家庭版故障处理（2026-10-26 用户确认简化）

- **只有三条使用路径**：正常使用；离线时检查连接并重试；确认原空间不再使用时，手动放弃旧绑定、重新建空白空间。无自动找盘、自动迁移、文件级自动修复或远程救援任务。
- 移除物理根只能由 Mac 本机管理员操作。只解除登记，绝不格式化、删文件；移除登记需等待活跃任务结束。不能把离线但**仍登记**的原盘当成新盘。
- Web 管理员在 `POST /api/v2/storage/users/{id}/categories/{category}/abandon` 明确确认原 `rootID` 和 `generation`，后端只在该 rootID 已从注册表移除后，原子解除该用户**这一分类**的旧目录绑定、成员授权、相应文件分享与逻辑容量账本。其他用户或类别不受影响。
- 此操作会**放弃旧类别的配额记录及可能未完成的上传预约**，不代表旧文件已被物理擦除、归档或自动迁移。用户须明确接受旧数据需要自行处理。新分配的目录必须为空，避免把旧未计费文件冒充新空间数据。
- 已有安全存储身份、路径隔离、未确认写入保留预占等机制仍保留。WebDAV、下载等未接入账本的个人空间入口继续拒绝，`enforcement=pending` / `usageComplete=false` 不得修改为完整配额承诺。

## 隐私和首次初始化

- 分配根不等于授予整盘目录读取权限。个人成员默认私有目录，分享给家庭成员必须是单独的可撤销操作。首批只面向新安装的全新目录，不要求继承旧单根授权或旧媒体数据。
- 未指定存储位置的账号显示默认 100 GiB 意向值，但没有目录时不提供该类别写入。只有当真实写入全部完成统一限额拦截，才能移除 `enforcement=pending`。
- 备份存储策略在 `accounts.sqlite` 内跟随应用元数据快照；恢复到另一台 Mac 或盘更换时，旧 rootID/generation 不自动授权新介质，须管理员重新确认。

## 当前落地与开放门禁（2026-11-02）

- 实现文件：`core/internal/auth/storage_root_quota.go`、`storage_ledger.go` 与 `core/internal/server/user_storage.go`；表 `user_storage_root_quotas`，一次性迁移 `storage_quota_migrations/per_disk_v1`。读取策略使用 `rootQuotas`；旧全局 `quotaBytes:null` 不表示成员不限额。
- 全局 API `/api/v2/me/storage`；管理员单盘调整 `PUT /api/v2/users/{id}/storage/roots/{rootID}/quota`；旧总额写接口返回 409。根范围写入需校验代际。
- 私人目录创建、部分单文件上传/复制/移动与回收站清理已有预占或账本保护；WebDAV 与下载发布到私人目录安全拒绝，未涵盖的通道不会放开。
- **`enforcement=pending` / `usageComplete=false` 不得提前改为完成**。真实两盘并发写入、外置盘重挂、满盘、隔离恢复、Android/iOS 原片备份和数据保护测试通过之前，不当作稳定多盘硬配额发布。
- 过去关于全局配额或 v1 兼容的分阶段记录已从当前规范移走，历史可在 Git 查看。详见 [STATUS](../STATUS.md)、[ROADMAP](../ROADMAP.md) 和 [STORAGE_AND_DISKS](../STORAGE_AND_DISKS.md)。
