# ADR 0003：个人空间、分类存储位置与跨盘统一配额

日期：2026-10-26。状态：**以全新安装/新账号为目标，分阶段实施；不得把配额设置称作已生效的写入限额。**

## 产品约定

LightIsle 的 RootRegistry 负责**物理共享根**（可以是不同硬盘上的专用文件夹）；本 ADR 在其上叠加**用户私有空间**。一个物理根可以容纳多个用户，每个用户可以把不同类别的内容放到不同根。用户看到的是“我的文件 / 我的照片 / 我的视频”，不应被迫先理解 rootID。

- 每个账号（含管理员）具有固定的逻辑存储位置。类别为 `files`、`photos`、`videos`；下载归入文件类别，不额外赠送一套容量。照片、视频、普通文件可分别指向不同根，同一用户的多个类别也可在同一硬盘。
- **目前按全新安装交付**：管理员先在 Mac 登记多根硬盘，再在 Web 中选择默认根创建账号；Web 在创建成功后为新用户自动请求 files/photos/videos 三个目录的创建与授权。管理员仍可单独给自己分配目录，照片、视频也可按类别单独指定盘。若创建账号时尚未选择在线根，账号仍可创建，需在存储面板手动分配。
- 配置使用 `(user_id, category, rootID, rootGeneration, relativePath)`；相对目录由系统生成 `Users/u{userID}/{category}`，以不可变数字 ID 而非可重命名用户名命名。路径必须先由物理根租约确认，RootRegistry 永不通过路径猜测替换磁盘身份。
- 管理员的个人配额为**不限制**（JSON `quotaBytes:null`），但仍受硬盘实际剩余空间和系统文件写入限制。所有非管理员角色默认 **100 GiB = 107374182400 字节**，后续由管理员逐账号调节。
- 非管理员配额是**该账号跨全部分配根/类别的一个总上限**，不能把每个盘都再分配 100 GiB。用户看到总已用、上传预占与剩余；管理员可以查看不同硬盘的分类用量。
- 用户默认只访问自己的目录，额外共享依然走现有授权模型；管理员作为维护者有权管理所有用户。根授权 `.` 不能作为私有用户目录的数据泄露捷径；必须继续审查通过根级媒体索引、旧版 v1 API 和 WebDAV 访问私人目录的边界。

## 用量与写入计费

个人版优先按文件逻辑大小（字节）统计，不实现块级去重、存储池或跨硬盘物理配额。

1. 原始文件计入所属用户配额；缩略图、转码缓存和 SQLite 元数据不计。**回收站仍计入**直到真正清除，避免利用删除/恢复绕过额度。跨盘同一用户“移动”只计一次（复制过程中仍须单独检查真实空闲空间）。
2. 开始上传时按声明总大小预占，服务端跨根原子记账。直接 PUT、分块上传、Android/iOS 照片备份、WebDAV、下载中心发布、文件复制及恢复等所有写入路径必须共用同一配额预占/提交/释放机制；不能只拦截浏览器上传。
3. 同账号并发上传不能绕过总额。异常或介质离线时不自动清空账本、也不盲目释放不确定的上传预占；有问题时提示管理员自行检查。容量无法验证时应**拒绝新增超额风险写入**，不能误称还有 100 GiB。家庭版不开发企业级周期实盘扫描修复器。
4. 管理员向成员目录写文件时，应计入**目录所有者**的配额，而不是利用管理员无限额度绕过。缩小额度到低于已用时只禁止新的增量写入，不自动删除文件。
5. 如果目标根离线，本类别写入失败并提示检查连接，不偷偷转写到另一个盘。家庭版**不做自动跨盘迁移**：确认旧空间不用后，管理员在 Mac 上移除硬盘登记，回到 Web 解除对应账号的分类绑定，再选择新盘创建空白目录；原盘原件不被格式化或删除。

## 家庭版故障处理（2026-10-26 用户确认简化）

- **只有三条使用路径**：正常使用；离线时检查连接并重试；确认原空间不再使用时，手动放弃旧绑定、重新建空白空间。无自动找盘、自动迁移、文件级自动修复或远程救援任务。
- 移除物理根只能由 Mac 本机管理员操作。只解除登记，绝不格式化、删文件；移除登记需等待活跃任务结束。不能把离线但**仍登记**的原盘当成新盘。
- Web 管理员在 `POST /api/v2/storage/users/{id}/categories/{category}/abandon` 明确确认原 `rootID` 和 `generation`，后端只在该 rootID 已从注册表移除后，原子解除该用户**这一分类**的旧目录绑定、成员授权、相应文件分享与逻辑容量账本。其他用户或类别不受影响。
- 此操作会**放弃旧类别的配额记录及可能未完成的上传预约**，不代表旧文件已被物理擦除、归档或自动迁移。用户须明确接受旧数据需要自行处理。新分配的目录必须为空，避免把旧未计费文件冒充新空间数据。
- 已有安全存储身份、路径隔离、未确认写入保留预占等机制仍保留。WebDAV、下载等未接入账本的个人空间入口继续拒绝，`enforcement=pending` / `usageComplete=false` 不得修改为完整配额承诺。

## 隐私和首次初始化

- 分配根不等于授予整盘目录读取权限。个人成员默认私有目录，分享给家庭成员必须是单独的可撤销操作。首批只面向新安装的全新目录，不要求继承旧单根授权或旧媒体数据。
- 未指定存储位置的账号显示默认 100 GiB 意向值，但没有目录时不提供该类别写入。只有当真实写入全部完成统一限额拦截，才能移除 `enforcement=pending`。
- 备份存储策略在 `accounts.sqlite` 内跟随应用元数据快照；恢复到另一台 Mac 或盘更换时，旧 rootID/generation 不自动授权新介质，须管理员重新确认。

## 分批开发和上线门禁

### 第一批：数据模型及管理 API（2026-10-26 开始）

- `core/internal/auth/storage.go`：用户统一配额设置、分类目的地持久化；管理员不设额度，非管理员默认 100 GiB。
- `user_storage_quotas` 和 `user_storage_locations` 存于既有 `accounts.sqlite`，未配置的旧账号兼容默认；RootRegistry 仍是唯一物理身份信任源。
- 管理 API 返回 `enforcement:"pending"`，**不表示真实写入限额已生效**。变更目的地拒绝静默换根/换代，不执行文件搬迁。

### 第二批：安全落地私人目录和硬配额（目录已实现，配额继续）

- 已在受信任根租约下按 UserID 创建 `Users/u<ID>/<category>`，并在账号数据库同一事务里保存存储位置和专属目录授权；根离线时不静默改盘，目录冲突则拒绝。新用户在 Web 选择了当前在线根时自动初始化三个类别。
- 先实现扫描/账本/上传预占接口，再让所有会增加成员使用量的写入渠道接入；同步补权限拒绝、双并发、重启、磁盘满/离线测试。**完成之前不能在正式版标称“限额 100 GiB”。**

**2026-10-26 账本批次进展**：

- 已在 `accounts.sqlite` 新增 `user_storage_files` 和 `user_storage_reservations`，每条记录带账号、rootID、rootGeneration、相对文件路径及逻辑字节大小。跨根使用同一个数据库事务串行预占，不能并发超分配。
- `PUT /api/v2/roots/{rootID}/files/content` 对已分配的私人目录先按 HTTP Content-Length 预占，再经安全文件 API 写入，持久化成功后计入已用；未知长度在私人目录拒绝。分块上传创建阶段预占完整申报大小，取消成功才释放；块补写与最终发布检查关联预约，完成发布再转正式已用。
- 用户目录内不允许尚未接入账本的移动/复制绕过，先返回 `storage_mutation_accounting_pending`；移入回收站仍保留计费，**永久清除成功后**从账本释放所占字节。
- 崩溃恢复策略偏安全：SQLite 预占跨进程重启保留，发布成功但账本提交失败时保留预约并报告 `storage_accounting_uncertain`，**不在超时后盲目释放**。下一步需实现带有真实介质固定身份、无活动写入的人工/周期校准；遇到离线盘不允许把字节归零。
- 管理接口返回 `accountedBytes` 与 `reservedBytes`，UI 明确标为已接入渠道的账本读数；`usageComplete=false` / `enforcement=pending`，尚不能当作全盘真实占用或正式硬配额。
- **尚未接入** WebDAV（旧 v1 和其他 DAV 写入）、下载中心发布、后台媒体导入及任意外部进程直接修改磁盘。扫描校准、跨类别自动路由、目录移动/复制操作尚未闭环。确保它们接入前继续标 `pending`，不在生产版本把新额度当作硬限制。

**2026-10-26 P0 账本旁路封堵（正式渠道计费仍待做）**：

- 旧 v1 HTTP 文件读写/搜索/目录列表与传统 WebDAV 均不能触达新的 `Users/` 私人根，避免旧式全盘授权跨越 v2 代际和用户归属；WebDAV 目录列表不暴露私有目录。原有普通共享目录仍可照常用 DAV。
- 旧下载中心禁止把任务目标设为 `Users/...`，导入前也逐项预检 aria2 暂存的**嵌套相对路径**；曾经创建的任务同样不可发布到个人空间。要支持下载到“我的文件”，必须先实现真正的带根代际身份、用户级预占和可恢复的发布事务。
- 直接上传若已发生发布但未获得持久性确认，绝不释放配额预占；普通用户/管理员删除分块暂存时，在同一上传互斥锁中同时检查暂存和最终路径，只有确认未发布才自动回收预占。人工清理无法确定归属的预占仍需未来实盘对账，不得因超时自动扣减。
- 这些是**失败时拒绝写入的安全修复，而非已经实现全部写入通道**；继续保留 `usageComplete=false`、`enforcement=pending`，并用跨用户读写/历史任务/取消竞态回归测试覆盖。
- **macOS APFS 大小写不敏感保护**：私有 `Users/` 命名空间按不区分大小写判断（包括 `users/` / `USERS/`），否则旧 API 和账本可能把同一物理目录当成非私人路径；root 会话权限和基于账号 ID 的媒体/后台辅助读写检查同样拒绝其他用户的目录。过期暂存自动清理也仅移除经核对未发布的项，疑似已发布者保留待对账。

### 第三批：统一用户入口和分类媒体归属（界面已接入，自动路由仍待完善）

- Mac 多根管理页指引到 Web 用户存储界面；Web 管理员可更改配置的配额并逐类别分配硬盘，Web/Flutter 用户端均可查看自己的配额配置及目录；Flutter 管理员可调整配额并分配目录。Mac 的独立本机管理编辑入口、跨类别自动路由与真实剩余空间读数仍待完成。
- 图库/影视索引查询按用户所有权过滤，避免同盘多个用户之间因全根媒体扫描而串数据。全新用户优先使用新结构，旧 v1 客户端保持兼容直至迁移。

### 第四批：新安装与真实设备验收（不做旧数据迁移）

- **用户明确表示尚未使用 LightIsle，放弃旧单根数据迁移需求**。本轮不编写旧权限/相册/播放进度迁移 UI 和升级计划；历史预览代码可以保留作为未来兼容参考，但不成为新安装 Beta 的发布门禁。
- 真实两盘反复插拔、相同路径换盘、成员登录互访、100 GiB 边界、上传中断、回收站/恢复、配置备份/还原验收，全部完成后开放多根正式功能开关。

**重要：第一批仅实现设置的持久化和权限校验，不创建目录、不变更现有成员 ACL，也不宣称启用了写入拦截或自动数据迁移。**
