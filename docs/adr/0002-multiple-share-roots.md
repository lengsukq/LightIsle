# ADR 0002：多共享根与按根授权

日期：2026-10-23。状态：已接受；**隔离的 Core/API v2、上传、分享、媒体、任务、备份及 Web/原生开发预览已接入并有回归**。开发开关默认关闭；旧账号授权/个人媒体迁移、统一多根恢复 UI 与真机验收尚未完成，禁止宣称多根正式交付。最新证据见 [续做记录](../MULTI_ROOT_RECOVERY_PROGRESS_2026-10-23.md)。

## 背景

当前文件管理器在进程内只持有一个可变共享根。文件 API、授权、分享下载、续传、照片与影视索引、任务和备份都隐式依赖这个“当前根”。在请求或后台扫描的多次文件访问之间切换根，会让操作读取新根，却仍以旧路径或旧索引命名空间写入。路径不是稳定身份：同一路径可被新卷替换，卷也可换挂载点。

本决定面向个人 macOS arm64 应用。根登记仍由现有应用进程管理；不新增守护进程，不改变窗口关闭或应用退出时的服务生命周期。fnOS 对标文档是产品优先级输入，不改变本 ADR 的安全边界。

## 决定

### 根身份与登记

- 每个登记根有持久随机 UUID `rootID`、用户名称、规范路径、物理 `Binding` 和单调递增的 `generation`。`rootID` 标识应用内的逻辑根记录；`Binding` 标识该记录当前绑定的卷和目录对象。物理身份不完整或无法确认时，根保持未绑定/离线，不能以路径猜测身份。
- `Binding` 使用 `core/internal/storageidentity` 的 API。路径变更时用 `SameObject` 识别同一个底层目录；完整字段比较使用 `Equal`。显式 `Rebind` 更新绑定并增加 generation，使此前租约失效。物理绑定不可用或发生冲突时保留原记录为离线，不自动指向 `SharedFiles`。
- 根登记簿有版本号，原子持久化在应用数据目录；最多 16 个根。只允许用户主目录下的文件夹或 `/Volumes` 下的卷内目录。任意两个登记根在规范路径上不能相同、互为祖先/后代，也不能绑定到同一底层目录对象。
- `Add` 只接受当前存在且可捕获完整物理身份的目录。`Remove` 只解除登记，不删除根内用户数据；当前实现中 `Remove/Rebind` 在仍有租约时返回 busy，等待请求/扫描/备份结束后由所有者重试，避免强行中断任务。空闲时移除记录或重绑并增加 generation；移除的 rootID 不复用，旧能力不能指向新登记。

### 访问租约

`Acquire(rootID)` 返回租约，固定该根的 `Store`、路径、物理绑定和 generation。租约 `State` 不会随其他根的选择而改变；`Valid` 检查根仍登记、generation 未变、物理身份仍匹配；`Close` 释放引用。所有请求、扫描、上传、分享和备份必须在开始时取得一个租约，并在提交持久化结果前检查租约仍有效。旧句柄永远不能重新解析成另一个根。

Root registry 可以同时持有并租用多个 Store。不得通过对单一 `Manager.SetRoot` 进行切换来冒充多根；`SetRoot` 不能作为根选择或请求路由器。

### 请求、权限和媒体数据契约

- 新 HTTP API 的根选择位于路径中，例如 `/api/v2/roots/{rootID}/files`、`/api/v2/roots/{rootID}/photos` 和 `/api/v2/roots/{rootID}/cinema`。`GET /api/v2/roots` 只返回当前用户有权访问的根。RootID 是不可信输入，服务端必须先确认根在线并获取租约，再校验根范围内的路径权限。
- 授权键是 `(user_id, root_id, relative_path)`，写权限也按根独立存储。相同相对路径在不同根不继承权限；`.` 只代表指定根的根目录。管理员登记根不会自动给成员授权。
- 分享 token 记录并解析出 `rootID`，每次下载按该根取租约、重新验证创建者当前对同根路径的读取权限并核对文件指纹。授权撤销只撤销受影响根下的 token。
- 上传状态包含 `rootID`；开始、状态、分块、完成和取消必须校验路由根与会话根一致。分块文件仍放在对应根自己的 `.lightisle-parts` 中。
- 照片/影视数据、收藏、相册、观看进度、缩略图缓存和每次索引任务都带根身份。每个数据库查询、连接和变更必须限定同一个根；资产/影片 ID 不能脱离 rootID 解释。扫描任务固定租约，不得在分页、媒体探测或写库之间重新解析“当前根”。任务状态、历史、取消和根相关告警按 `(kind, rootID)` 区分。
- 备份计划绑定明确源 `rootID`，任务固定该根租约并记录 rootID 与物理 Binding 身份。备份目的地必须与所有已登记根不相交；新增根也不得落入备份目的地。现有 `Manifest.SourceRootID` 表示卷 UUID 加目录物理身份，必须保留其旧含义，新增独立逻辑根字段，不得复用或静默重解释。

无 rootID 的旧 API 只保留为单根兼容面，固定到迁移产生的兼容根；它不提供多根切换。用户新增 Flutter 代码不在本阶段修改。若要让不携带 rootID 的客户端选择多个根，必须另行改客户端契约，不能由服务端猜测。

### 迁移与恢复

- 首次发现旧 `shared-root.json` 时，只迁移它描述的一个兼容根，并将生成的 UUID 原子保存进新版登记簿，保证后续重启稳定。path-only 旧配置视为未确认绑定并保持离线，直到原生目录选择器显式重新绑定；若旧配置包含完整且可验证的 Binding，则保留该绑定。迁移失败或配置损坏时拒绝启动登记簿，不回退到默认目录。
- 没有任何旧共享根配置的首次安装可以创建并捕获默认 `SharedFiles` 根。外部旧根离线时不得创建或切换到默认目录替代它。
- 旧授权只映射到迁移出来的兼容根，不复制到新根。旧 Gallery/Cinema 记录只有在原 `share` 路径能明确归属该根时才迁移；其余记录保留为未绑定数据。旧分享记录缺 rootID，迁移不能证明 token 的根归属时应撤销而非跨根续用。已有根内上传 journal 只能由其所在根恢复。
- `shared-roots.json`、根范围媒体数据和根身份必须纳入备份、离线恢复与回滚清单。恢复时仅在 rootID 和物理身份匹配或用户显式确认重新绑定后恢复；不能因路径相同就将备份写入另一个根。

## 交付顺序与开放门禁

当前已有可持久化、可验证、可并发租用的 Core RootRegistry、独立 root_file_grants/root_file_shares、逐根服务与业务路由，以及受显式开发开关保护的 Web/原生预览。共享登记和备份只经原生私有管道；旧单根继续保留 v1，不自动迁移旧权限与私人相册。Core 初始化阶段加载登记簿，配置损坏或发布同步不确定则失败封闭；每根数据库的固定文件名进入元数据导出/恢复白名单，恢复仍核对物理身份。**默认不返回根发现接口，不开放多根正式用户入口**；旧迁移与恢复 UI 闭环、真机验收完成后才评估解除开关，不得让未隔离的旧 API 切换到额外根。

核心回归至少覆盖：两个根内相同相对路径互不串读写；多个租约同时有效；rebind/remove 使旧租约失效并等待释放；卷离线/挂载点替换不会改写其他根；重启后 rootID 稳定；path-only 旧配置迁移为离线兼容根；损坏或半成品配置拒绝且不回退默认目录；根数上限与路径/物理身份重叠均被拒绝。
