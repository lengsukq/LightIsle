# Web 文件上传故障与交互优化（个人 Beta）

## 修复的问题

- 原上传逻辑把上传异常和文件列表异常都写进全局 filesError，然后无条件刷新文件列表。loadFiles 每次先清空 filesError，导致**上传失败信息会转瞬消失**，用户无法判断失败原因。现在区分 uploadFailure 和 filesError；只有已成功发布文件时才重新拉取目录，因此失败结果不会被列表刷新覆盖。
- 旧上传进度只有一行文字，先完整校验再上传的阶段不清晰，多文件上传没有整体数量，完成立即消失。现提供固定进度卡片：校验进度、传输进度、文件序号、上传字节、完成/失败、手动关闭、取消。
- 重选同一文件浏览器 change 可能不触发：点击选择文件前清空 input.value，上传入口和拖放复用同一个处理函数。
- 常见后台错误改成直观提示：同名文件阻止覆盖、目录只读、离线卷、权限拒绝、库存限制、身份不符、持久化结果不明。失败不悄悄覆盖已有文件，续传维持之前完整内容指纹隔离，单文件仍最多 32 GiB。
- 使用项目已有的玻璃拟态、大圆角和低饱和色系设计拖拽区及进度反馈；不引入新的主题系统或第三方上传依赖。

## 验收

- Web Vue 类型检查与 Vite 生产构建、原有 Node 上传身份与完整内容指纹测试通过；Core 上传服务现有 Go 回归也通过。
- 尚需浏览器端真实拖拽、连续上传多文件、Safari / Chrome 取消和续传交互真机检查；现有 mock/Core 单元不能证明浏览器原生文件选择器在所有系统环境下稳定。
