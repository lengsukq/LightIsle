# LightIsle 个人版 Beta：离线硬盘与格式化入口

## 用户问题
- 当前挂载的 NTFS 卷（示例：`Untitled`）在 macOS 通常只读。不能绕过系统挂载权限直接作为可写共享盘。
- 曾授权的外置盘未连接时，保留原磁盘身份绑定，不可悄悄用同名目录或系统盘代替。
- 需要“保留，等待重连”及“清理离线磁盘的 LightIsle 记录”两种明确选择。

## 本轮实施
1. Core 输出曾配置但离线的原始共享路径（私有父进程 IPC）；Mac 显示断开位置、提示接回原盘，默认维持原绑定。
2. 增加仅在**原共享盘实际离线**时可使用的本机「解除离线盘绑定并清理媒体记录」动作。需完整输入二次确认；Core 重新绑定到 Mac 用户应用数据中的默认 `SharedFiles`，旧磁盘**任何真实文件均不删除**。旧路径对应的本地图库、影院索引（含其相册关联、收藏和观影进度）将清理，其他共享路径索引不得受影响；清理旧共享根的成员权限、匿名分享链接及对应兼容根登记，防止继承到新根；管理员账号和应用备份不清理。若 Core 无法验证或完成切换则应拒绝操作，不尝试对未挂载盘擦除文件；记录错误和残留状态。
3. NTFS/只读卷给出明确文件系统说明。为外置卷提供「格式化为 Mac 可写磁盘…」入口，**仅跳转系统磁盘工具，由用户亲自选择正确物理设备并执行系统抹盘确认**；界面指导 APFS（Mac 专用）或 exFAT（Mac/Windows）。LightIsle 不调用 `diskutil eraseDisk`、不提权、不后台格式化、不假称自动完成。
4. 单共享根/多根预览互斥、备份和传输期间不可清理当前绑定；写入错误提示与单元/打包冒烟，最后检查 Git 工作区保留其他开发任务。

## 重要风险边界
- 用户尚未明确请求**立刻擦除某块磁盘**，所以任何测试、构建和本轮应用代码都不得自行执行实际抹盘。
- 清理离线磁盘的 LightIsle 媒体记录属于不可撤销的本地元数据删除，可能丢失收藏、播放进度等，应先独立备份私有应用数据。旧外置盘重新接回后原始文件仍在，但需要手工重新授权和重建索引。
- macOS 磁盘工具抹掉物理卷会破坏该卷现有文件；用户必须在系统工具内确认目标与格式。外接 NTFS 只读不是磁盘坏掉的充分证据。

## 实施与验证记录

- Go Core 原有共享目录通过 shared-root.json 绑定物理目录身份；新增 share forget 命令仅父进程私有管道可调用。必须实际离线、路径匹配、无备份/扫描/外部传输任务，不允许多根预览模式执行。成功后重新绑定到本机 SharedFiles，清理旧路径媒体索引、照片收藏与相册、影片观看进度、v1 成员授权/匿名分享，及对应 v2 兼容根记录（如果存在），保留其他根与所有实体文件。
- 存在因异常退出、SQLite 或配置 fsync 失败而只清理一部分的风险；通过 Core 特定告警让原生界面提示需重启、检查存储路径与独立备份，不假装跨数据库操作是原子事务。
- 对截图的 NTFS 盘：只读由 macOS 文件系统支持能力决定，与 SMART 是否可读取是两件独立的事；部分 USB 桥接设备无法提供 SMART 指标。
- **本地安全测试**：Go 模拟卷离线、相同路径被替换、不同目录索引和权限隔离；打包冒烟 tests/test_offline_share_forget.py 使用用户 Home 下的全新临时目录，不接触真实外置盘。本次没有实盘执行「抹掉」操作。
