# 用户可理解的错误提示约定

> 面向个人和家庭用户。错误码是 API 与日志使用的稳定标识，**不能作为 UI 唯一提示**。

## 用户应该看到什么

提示至少覆盖：**什么事情没完成 → 可能原因（能确认时）→ 是否影响数据/原操作 → 用户下一步做什么**。

| API/IPC 标识 | 不合适的提示 | 建议提示 |
| --- | --- | --- |
| `volume_offline` | 读取失败：volume_offline | 原硬盘离线或重新挂载后尚未确认。到 Mac「数据与存储」检查原盘、重新连接，再点击重试。 |
| `file_permission_denied` | 权限错误 | 当前账号无权访问该目录，请联系管理员检查授权。 |
| `storage_quota_exceeded` | 保存失败 | 个人存储额度已用尽。请清理空间或联系管理员调整额度。 |
| `HTTP 503` | HTTP 503 | NAS 服务或存储暂时不可用，请确认 Mac App 是否运行、硬盘是否在线。 |
| `download_publish_failed` | 下载失败 | 下载已完成，但保存到共享目录失败。请核对存储状态和目标文件，避免重复覆盖。 |

## 开发规范

1. **不要把通用异常对象、HTTP 状态码、下划线式错误码直接渲染在页面上**；调用平台级公共翻译器，允许页面进一步给出具体语境（例如上传保留进度、分享撤销不会恢复）。
2. Web 使用 `apps/web/src/userFacingError.js` 的 `describeUserFacingError`，Flutter 使用 `apps/flutter/lib/core/user_facing_error.dart` 的 `userFacingError`，Mac FRP/Tunnel 私有 IPC 通过页面中的错误码转换逻辑展示。
3. **不能猜测数据结果**：请求超时、磁盘同步不确定、批量操作部分完成等，只说明「状态未确认，请刷新核对」，不能假装成功或说文件肯定丢失。
4. **保留安全边界**：离线卷的数据库索引也不能直接当成当前可授权内容使用，不绕过卷物理身份、权限、登录会话等检查。
5. 后端及日志保留稳定错误码便于定位；普通 UI 首先显示人话。未知标识可以附在可操作提示后面供诊断，但仅显示符合 `[a-z][a-z0-9_]{1,80}` 的短标识，禁止透出令牌、访问 URL、文件路径或长异常内容。
6. **不要重复翻译已有完整中文错误**，尤其 SSL 证书指纹、macOS Keychain 和受限文件操作等可能包含重要恢复步骤。
7. 新增 API 错误码时同步补跨端对应映射和测试；优先测试离线、无权、服务未启用、连接断开、重复提交和返回未知码。

## 验证

- Web：`cd apps/web && npm test && npm run build`
- Flutter：`cd apps/flutter && flutter analyze && flutter test`
- Mac：`swift build -c release`
- 手动验收：使用实际外置盘、不同权限的成员与无网络设备验证具体错误和恢复路径；上述静态检查不等于真机验收。
