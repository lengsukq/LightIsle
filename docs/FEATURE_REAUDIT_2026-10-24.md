## 本轮优先项

| 优先级 | 发现 | 本轮处理 |
| --- | --- | --- |
| P0 | 磁盘保护只比较路径，原 NAS 卷换挂载点可能失去保护 | 按已绑定卷 UUID 保护，覆盖默认根和注册根；后台导出期间拒绝磁盘动作 |
| P0 | 启动时原盘离线导致文件 Store 未打开，重连后清理仍可能误判离线 | 清理前重新确认绑定/卷状态，拒绝对已重新上线的根执行离线记录清理 |
| P1 | 复制/移动后是否刷新列表错误依赖先前上传成功数 | 操作成功即刷新；上传批次另行只在已发布文件时刷新 |
| P1 | 取消恰逢上传创建响应返回，会丢失任务 ID | 先接收任务 ID，再检查取消；清理使用上传时捕获的根路径 |
| P1 | 多文件批次部分完成后重选整批，会先撞已经存在的文件 | 提供明确的继续未完成文件入口，保留原账号、根、目录上下文，切换后失效 |
| P1 | 回收站请求失败或尚在加载时显示空 | 加载/失败/空/内容互斥，并提供重试和旧请求结果屏障 |
| P1 | Android 已有原生发现接口，但 Flutter 登录页没有调用 | Android 登录页增加显式局域网发现，只填本地 HTTPS 地址，仍需核对指纹并手动登录 |
| P1 | 背景过强、图库/影院内容直接压在彩色背景上，相册动作分散 | 降低背景色强度，增加清晰内容面板，窄屏相册操作换行，并明确共享/私人相册 |

## 已有功能核实

- 默认单目录的 `/api/v2/roots` 返回 JSON 404，Web 使用 v1；HTML 200、服务错误和解析错误仍显示可恢复的失败状态。文件、照片和影院共用状态卡。
- Mac 存储位置选择、离线解绑、格式化系统入口和磁盘管理已有实现，不重复创建另一套配置或操作引擎。格式化继续由用户在系统磁盘工具亲自确认。
- Android 系统后台备份已有显式开关，开启后立即排一次扫描，后续约六小时由系统调度；前台检查和系统后台备份是两个独立入口。真实厂商省电、锁屏、大图库和调度时机仍需设备验收。

## 后续优先级

1. 真实 Android 与 Mac 局域网：Bonjour 可发现、证书变更核对、断网重连、照片后台补跑，记录设备与网络条件。
2. 外置盘人工验收：只在可丢弃数据、未用于 NAS 的盘验证重挂、重命名、繁忙拒绝和同名替换；任何真实磁盘变更均应由用户明确发起。
3. 媒体错误反馈：共享相册接口加载失败目前有静默处理路径，需要补独立可重试提示；影院定时状态失败同理。保持已有内容，避免空列表掩盖网络错误。
4. 后台备份页面在恢复前台时刷新系统任务状态；按实际需要评估“立即后台补跑”，不承诺系统准点执行。
5. 多根迁移、真实恢复、长时间稳定性、Developer ID 签名与公证仍按既有发行门禁完成，不能从本轮单元和开发构建推断已发布可用。
