# 个人 NAS 功能审查与实施计划

> **2026-10-23 最新个人版产品裁剪：** [macOS 原生能力优先的 fnOS 对标与排期](FNOS_PARITY_PRIORITIES.md) 是本项目**最新需求优先级依据**。该文决定只做个人 NAS：复用 APFS/系统 SMB/Time Machine/SQLite，移出企业级联合灾难恢复、跨盘事务引擎、自研增量备份。本文下方原批次/子代理记录是**历史实施审查快照**，包括当时列为第三阶段的联合灾备、目录级移动等，**不再意味着当前需要开发或阻断发布**。当前代码事实可参考 [最新复审记录](REAUDIT_AND_EXECUTION_2026-10-23.md)。

> **Flutter 范围增补（2026-10-22）：** 用户新增要求实现 Android、macOS、iOS Flutter 客户端，工程位于 `apps/flutter`；这更新了本文原先“仅 Mac/Web、不安排原生移动端”的客户端范围。NAS 后端与原生管理端仍为 macOS arm64，生命周期和本机权限边界不变。[实现与验证记录](FLUTTER_CLIENT.md)。

> 基线：2026-10-22，依据当前工作区代码及三个 GPT-6 Luna（max）子代理的独立审查。目标是接近 fnOS 的日常使用体验，面向个人，仅交付 macOS arm64 应用。本文更新历史路线图的产品范围；有代码不等于已通过真实磁盘、GUI 或正式发布验收。

## 产品取舍

轻屿是一个人在 Apple Silicon Mac 上管理自己的文件、照片、影视和备份的空间。保留原生管理端 + 浏览器业务端；打开 App 启动服务，最小化继续运行，关闭最后一个主窗口或 ⌘Q 停止服务。此轮不改变这项既有生命周期约定。

- 唯一安装与原生适配目标：macOS arm64。Linux、Windows、Intel Mac、Android/iOS 原生客户端不进入当前计划。现有 Web 浏览器访问保留，不等同于新增系统客户端。
- 个人流程优先：首任管理员直接使用，成员与目录授权作为已有可选能力保留，不把团队、企业审批或多租户流程放在主路径。
- 对齐 fnOS 的文件、相册、影视、备份、任务与状态反馈等日常能力。参考：[fnOS 官方功能介绍](https://fnnas.com/)、[官方帮助中心](https://help.fnnas.com/)。这里是产品方向参考，以下完成度判断均来自本仓库代码。
- 适应 macOS 的真实能力：普通文件夹、APFS/外置卷、系统原生授权和只读磁盘诊断。不计划复制 Linux 存储池/RAID，也不将容器引擎或 AI 模型作为启动依赖。
- 不自动下载 FFmpeg、模型、海报、字幕或其他资源。需要外部资源的批次必须先列出资源、来源、目的地和用途，取得用户许可后再接入。

### 第二阶段：形成个人媒体空间

依赖第一阶段可靠性通过；优先使用系统已有 ImageIO/AVFoundation，无外部下载依赖。

1. 本机媒体 Worker：读取 HEIC 拍摄时间/方向，按需生成视频与影视封面，单任务超时、取消、并发/缓存上限；损坏素材有明确失败状态。
2. 照片分页与虚拟列表；相册改名/删除/移除成员闭环；共享收藏明确命名，之后再决定是否迁移为每用户收藏，避免静默改变既有数据归属。
3. 影视媒体探测和可解释的可播放状态，支持本地海报/元数据文件；在线播放失败提供下载/本地播放器路径。外部自动刮削默认关闭，先取得网络许可并确定来源与许可。
4. 必要时引入 arm64 FFmpeg/VideoToolbox/HLS；先确认具体来源、版本、分发许可、落盘位置和用户许可。兼容表覆盖直放/转码、音轨/字幕、缓存满/任务取消/退出无残留。

验收：真实 HEIC/JPEG/视频/损坏文件；1 万素材的滚动与内存；有代表性的电影/剧集样本；App 退出无 Worker 残留。不能用扩展名或编译成功代替播放验证。

### 第三阶段：让个人数据可长期托管

1. 备份目录清单与容量展示，显式设置保留数量；只清理可识别、完整且属于本计划的旧快照，成功新快照之后才轮换，手动快照默认保留。
2. 备份目标卷身份记录与重挂校验、缺盘/空间不足事件；失败可手动重试；与本次新增的“路径重定向拒绝”分开验收。
3. 孤儿上传的管理员列举和取消/到期清理，明确所有者/权限撤销后的处理，绝不清理正在提交的上传。
4. **历史计划（已被最新范围裁剪）**：成功离线激活后的元数据回退开发版已加入，仍要做真实恢复演练；**不再追加文件与数据库自动联合灾备引擎**，改为 Time Machine 数据卷覆盖核验 + 独立一致性 SQLite 备份与恢复。
5. 多个授权根与浏览器切换仍是高价值个人能力；跨卷优先使用系统操作与安全复制。历史通用持久队列和目录级复杂移动不再作为个人版必须交付；如保留可选移动，需复制验证、失败保源、明确提示，禁止未经确认永久删源。
6. 文件/图库 API 返回当前路径可写能力，界面按权限显示操作，后端继续逐次校验；明确共享收藏的权限归属。
7. 低空间、卷离线、备份失败与服务故障的事件中心；通过用户显式开启的系统通知交付重要事件，避免频繁弹窗。

验收：两块真实磁盘拔插/同名重挂、满盘、权限变化、10 GiB 文件与中断恢复；每步校验原始数据不受损。SMB 保留跳系统设置路径，特权自动配置与电源操作另行设计。

### 第四阶段：按个人需求补齐便利功能

文件夹流式 ZIP 下载、可信网络内有限期分享、全局搜索索引/媒体联合搜索、个人会话设备管理和操作审计。远程下载中心（先 HTTP(S)，BT 后评估）、Docker/Colima、AI 检索均为可选项，分别定义资源上限和网络边界，不阻塞核心 NAS。

### 第五阶段：可发布版本

版本化 SQLite migration、升级前元数据快照/回退、应用版本与故障日志导出、离线可用安装文档、arm64 二进制检查、第三方许可、Developer ID/公证。完成 Mac GUI/Touch ID/生命周期、物理卷、多用户权限、浏览器 HTTPS、72小时稳定性及干净机器安装验收后才改变“开发预览”标记。

## 第二阶段与长期托管增补（2026-10-22）

本批仍由三个 GPT-6 Luna、max 子代理分别完成媒体、上传维护和备份清单，主代理审查、接入 Web/原生界面并做整包验收。唯一原生安装目标仍是 macOS arm64。

已实现的产品行为：

- 随包的 Swift 媒体 Worker 使用系统 ImageIO/AVFoundation，通过已打开的只读 fd 读取素材；HEIC 拍摄时间和方向、真实视频容器/编码/尺寸/时长、照片缩略图及视频截帧封面已接入。限制并发、超时、输出与统一 LRU 缓存，不复制整个电影文件，不调用外部资源。旧方向错误缓存通过派生格式版本失效重建。
- 照片使用有界虚拟渲染和可取消的分页请求；相册改名、删除相册、移出照片均保留原件和共享收藏。空相册、空收藏有各自的引导。预览支持键盘焦点约束与关闭后恢复；预览/播放器从页面布局中独立挂载，避免侧栏遮挡。
- 文件列表、搜索和图库返回当前用户的可写提示；只读成员隐藏上传/创建/移动/删除/修改共享收藏入口，后端继续逐次校验。保留合法的只读源复制能力，目标目录仍需写授权。
- 管理员可在 Web 设置中分页查看未完成上传、账号状态及当前写授权，显式取消单项残留；7/30/90 天过期清理需确认且单次最多 100 项。写入/提交期间返回忙状态，扫描超限拒绝整批清理；已发布恢复记录需单独处理，不默认自动删除。
