## P0：升级前数据库预检

Mac 管理端「存储 → Beta 升级前安全检查」已接原生 Swift + SQLite3 只读检查，不依赖外部 Python。逐库读取最多 64 个 SQLite 文件、拒绝 symlink、缺少账号库或坏库 fail-closed，提示可能存在的 WAL 文件；不迁移、不修复、不删除、不自动升级。
原有 Mac 离线恢复预览、所有者身份确认、元数据激活与回滚功能仍独立存在。**必须人工完成独立外置盘数据备份和实际恢复演练**；预检成功不代表备份受到保护或升级兼容性已自动证明。

## P1：图库和影院增量扫描

原有 `StartScan()` 保留全量语义。新增 `StartScanDirs([]string)` 仅遍历 FSEvents 报告变化的已校验相对子目录。扫描完整、共享根身份仍一致、没有被取消时才限定清理该子目录的旧索引；避免跨目录的相册收藏和影片观看进度丢失。

Mac FSEvents 识别文件变动的**父目录**，每次最多聚合 32 个，最短约一分钟合并一次；丢事件、根变化、磁盘挂载或信息异常时回退全量。Go 私有父进程管道 `index dirs <base64url-json>` 接受有界相对目录列表，不能通过 Web/Flutter 接口指定任意磁盘扫描；周期性 15 分钟完整核对保留。多根开发预览仍不自动启用增量通知。

新回归覆盖 SQL 百分号、下划线目录名、路径穿越拒绝、错误目录不误删照片、跨目录收藏/观看进度保留。首次实际十万文件库与 macOS FSEvents 断流仍须真机核查。

## P1：Android 手机照片备份（当前为前台版本）

客户端「文件 → 手机照片备份」在 Android 下启用。通过 Android 系统权限按需读取 MediaStore 图片；分页最多 40 张，私有临时文件（单张最高 2 GiB），以账号/服务器来源/随机设备 ID 作为本地范围，按完整 SHA-256 标记上传成功。使用 NAS 已有的 4 MiB 分片、服务端偏移核对和续传会话，备份到 `PhonePhotos/<deviceId>`；Wi-Fi 选项默认开启；退出/暂停时不删除手机原片。

**Beta3 前台备份稳定性修复**：单次进入前台最多连续处理 10 页（最多 400 张），完成每页后持久保存扫描位置，暂停后优先续扫，用户也可明确选择从最新照片重查。上传完成后再以已认证 HEAD 检查远端文件存在及大小，才记录本机成功；丢失完成响应也会先检查远端再考虑重传。现代 Android 版本的跳过判断同时使用媒体数据库版本、图片变更代次、大小、修改时间和先前 SHA-256；数据库版本变化或旧 Android 无法取得代次时，必须重新读取原片计算 SHA-256，不会仅凭尺寸相同跳过。系统只授权部分照片时，不将其声称为完整相册备份；离开前台暂停，上传过程中持续检查 Wi-Fi。每次扫描仅读取有界批次，临时副本过期会清理，媒体查询在 Android 后台线程执行，不阻塞 UI。

**历史说明**：初版 Beta3 曾仅用远端 HEAD 判断存在与大小；该检查已由后续 Beta3.1 完整 SHA-256 核对替代，见下一节。实际 Android 设备运行仍待验收。

### Beta3.1：SHA-256 原片验收与可选 Android WorkManager 后台备份

- NAS Core 新增 `GET /api/v1/files/sha256?path=...`：沿用当前用户文件访问 ACL；限 2 GiB 普通文件，流式 SHA-256，读前读后确认打开文件及授权路径仍指向同一物理文件且大小/修改时间未变化。不提供公共外链或未认证哈希接口。多根 API 也经现有 RootID/Generation 和文件权限隔离。
- 校验请求采用有限的并发槽位，避免大量照片同时校验把 Mac CPU/磁盘占满。用户名单、敏感路径、Symlink、源文件变化和超 2 GiB 大文件等错误会拒绝校验；不能将文件大小相同等价为内容校验通过。
- Android 前台上传后须调用 NAS 端 SHA-256，**完整 64 位摘要和大小全部一致**才在手机记录成功；下次跳过已上传照片前同样独立校验远端完整内容。若目标路径已有不同摘要，不覆盖、删除或自动修复，必须由用户人工核对。端到端校验比先前 HEAD 检查更可靠，但对大图库会增加 Mac 硬盘读取、CPU 和联网请求。
- 用户可在「Android 照片增量备份」页面**单独、明确同意后**开启系统 WorkManager 后台任务，约每 6 小时按 Android 调度且满足 Wi-Fi/电量条件时尝试；App 关闭仍由原生 Kotlin Worker 执行，不依赖 Flutter 页面常驻。单轮最多检查约 30 张、每张后台处理上限 100 MiB；较大照片请前台处理。每个上传复用 Core 可续传分片协议，远端哈希不一致时失败封闭。**原始手机照片不会被删除**。
- 写入目录在已有 `PhonePhotos/<deviceId>` 可读且授权的情况下直接使用，不要求普通成员另有父级 `PhonePhotos` 的创建权限。首次新建共享目录时仍需要管理员预建，或当前账号具备相应父级写权限。
- **凭据安全权衡（重要）**：现有服务器尚未提供单独的、限权只写备份令牌，因此 WorkManager 经用户明确授权后，使用完整当前账号会话。该会话用 Android Keystore AES-GCM 加密保存在本机，最长 7 天到期，关掉后台开关、切换账号/服务器、退出登录或失去照片权限会主动清除并取消任务；Worker 在传输每个分片前复核任务代次，取消后不得继续提交。**建议为后台备份使用文件权限受限的普通成员账号，绝不承诺该令牌仅能用于备份目录。** HTTP 后台会话仅接受数字形式的私有/回环地址；HTTPS 由系统 CA 校验或使用原有配置的叶证书 SHA-256 指纹，关闭自动 HTTP 重定向，不向不同主机传 Cookie。局域网 HTTP 网络传输本身未加密，优先使用 Mac 上手动配置的 HTTPS。
- 备份计划不是固定闹钟：Android 的 Doze、后台策略、省电、权限和登录有效期会影响执行，强制停止 App 后不保证继续；Mac NAS 离线时后台任务将失败并等待系统重试。运行状态可从备份页面查看。**Android 真实锁屏、断网重连、多机型和 1000+ 张真实相册仍须设备验证**，本地 APK/Widget 测试不能替代这些证明。

**仍未完成验收**：Android 14+ 受限照片权限、不同厂商系统省电/Doze 策略、后台执行准点率以及大量照片和实际锁屏的真机验收。用户勾选“返回前台检查”只触发独立的 Flutter 前台任务；开启 WorkManager 需使用另一专门开关并明确授权。当前只复制普通图片，不自动备份视频/实况照片；额外大图片需要前台手动备份。用户须有 `PhonePhotos` 目录写权限和完整图片读取授权。

Android 构建输出 `apps/flutter/build/app/outputs/flutter-apk/app-debug.apk` 为调试包，不是正式签名发行物。

## P1：影片批量候选建议

Web「私人影院 → 批量整理影片 · TMDB 候选建议」由管理员明确触发：当前加载列表中最多 8 部待匹配影片，使用用户本次输入的 TMDB Read Access Token 顺序请求搜索候选。通过片名标准化、类型、年份保守评分；候选必须逐部人工确认，服务端重新获取候选详情再保存，不自动覆盖任意影片。不把 token 写入磁盘、URL 或日志；退出或切换根清空候选与密钥。

继续保留本地 NFO、TMDB 手工匹配及实验性的豆瓣网页建议降级；不把豆瓣的非官方查询视为正式结构化刮削服务。

## 不进入个人版的企业级能力

不开发 RAID/存储池、自研 SMB、独立常驻 NAS 守护进程、跨库文件联合灾难恢复/事务协调、自研增量块级备份平台。复用 macOS 文件系统、FSEvents、Time Machine 与现有 SQLite 备份恢复。
