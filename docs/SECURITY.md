# 安全模型与高风险操作要求

> LightIsle 要管理真实硬盘、用户文件与整机电源。安全是强制验收标准，而非后期插件。
> 后端仅运行 macOS arm64，不通过“兼容其他平台”弱化 macOS 权限边界。
> LightIsle.app 是 NAS 的唯一进程生命周期所有者，完全退出 App 后 Go Core 必须关闭；所有平台统一 iOS 27 风格，但设计外观不能代替权限与危险操作确认。
>
> **2026-10-23 个人版安全边界：** 优先复用 macOS 文件系统和 Time Machine，保留跨卷失败保源、路径权限、会话安全、SQLite 一致性备份及真实恢复验证；**不要求自研联合灾难恢复或企业级跨盘事务**。旧审查待办并非自动升级为个人版发布前提，最新范围见 [fnOS 个人版排期](PRODUCT.md)。本文混合“已实现”和“目标要求”，相关未验收项仍需按实际功能验收。

## 1. 信任边界

```text
LightIsle.app (SwiftUI，拥有 Go 子进程)
      │ 本地受保护 IPC / 启停
      ▼
Go Core（普通权限）◀── Android / Web 经 HTTPS + 设备会话
      │ 白名单及显式授权
      ▼
临时 Swift 系统辅助操作（按需，禁止常驻 root 服务）
      │
macOS 磁盘 / 系统服务 / 电源
```

- HTTP/API/管理页面为**非可信入口**，每个请求都做独立认证、授权和输入验证。
- Go Core 默认普通用户权限运行，不继承无限制 root 权限。
- **电脑文件只读访问**：总开关默认关闭，仅 Mac App 私有 IPC 可修改；HTTP 只能查询状态，由管理员按成员授予整机或指定目录，整机授权包括 Core 能读取的私人及敏感文件。服务端独立校验会话、总开关和成员授权，使用不跟随符号链接的目录句柄，只返回普通文件和目录。目录授权持久绑定卷 UUID 与目录身份；关闭或撤销会使进行中的读取失效。系统隐私保护及文件权限仍然生效，不以此功能提权或修改文件权限。
- 临时 Swift 系统操作无网络监听，不支持用户提交任意 Shell 命令、脚本或危险参数；退出 App 后不得保留特权后台进程。**当前 Swift Helper 尚未创建。**
- **SMART 提权（可选、只读、按需）**：Core 无权限读取设备 SMART 时，Mac App 可代为采集——先用 `sudo -n` 探测用户手动配置的 sudoers 免密白名单，失败则通过 `osascript … with administrator privileges` 弹出系统授权框。命令是固定模板（白名单路径的 smartctl + `--json -a /dev/diskN`），仅盘号变量且经严格解析，无任何用户字符串进入 shell；密码由系统安全代理处理，不经过应用代码。结果经私有 IPC 推回 Core 缓存（5 分钟 TTL），不安装、不残留任何后台进程；提权失败/取消均如实回退到 diskutil 基础状态。
- **macOS 系统 SMB 提权（可选、最小命令白名单）**：管理员在 Mac App「网络与连接 → Mac 文件共享」点击开启免密授权时，通过系统管理员授权框写入 `/etc/sudoers.d/lightisle-smb`（`0440`，写入前经 `/usr/sbin/visudo -cf` 语法校验，可随时一键撤销），仅授权当前宿主用户免密执行 `/usr/sbin/sharing *` 与 `/bin/launchctl load|unload -w /System/Library/LaunchDaemons/com.apple.smbd.plist`。Go Core 仅通过 `exec.CommandContext` 参数数组调用 `sudo -n`，不拼接 Shell；所有新增/编辑共享路径均校验属于已登记 `RootRegistry` 在线存储根，拒绝 `.lightisle-*`、`.Trash`、符号链接和裸系统卷，并记录 `smb_config_change` 审计日志。
- 任何磁盘、系统、共享操作应记录操作人、设备、对象、结果与 request_id。**账号/分享/文件等主要写操作已接入持久审计表及管理员 Web 查询**；统一 request_id、完整权限拒绝覆盖、防篡改及真实压力验收仍有缺口。

## 2. 用户、设备和远程连接

- 首次启动必须完成本地管理员初始化，禁止默认密码。已实现：仅 Mac App 私有 IPC 可初始化首任管理员，Web 不提供注册接口。
- 密码使用成熟的带盐 KDF（如 Argon2id），参数随目标设备性能实测；明文密码不落日志。当前使用 Argon2id（64 MiB、3 次迭代）。
- **Web 登录会话最长 30 天**，SQLite 的到期时间与 HTTP Cookie 共用同一期限。每账号保留最近签发的 100 个会话，过期会话与分享定期清理。本机管理员验证不签发 Web 会话；退出、停用账号、重置首任管理员密码会撤销相关会话。高风险操作重新认证仍只在部分本机操作中实现。
- **Flutter 登录保留**：最近一次有效会话经 iOS/macOS Keychain 或 Android Keystore AES-GCM 加密保存，不保存密码；重启须通过原来源/原证书指纹连接并由 NAS 重新验证身份，离线保留、到期/401 失效、退出清除。安全存储失败提示重试，不把凭据回退到明文首选项。
- 后台 API 必须防护暴力尝试、CSRF（若使用 cookie）、CORS 滥用、会话固定与权限提升。登录接口已有失败限流；Cookie 为 `HttpOnly` + `SameSite=Strict`，跨站写请求还需 `X-LightIsle-Request` 头。
- 直连 TLS 和本机回环代理声明的 HTTPS 会话使用 `Secure` Cookie。来自局域网的转发头不影响 Cookie 或限流地址。
- 局域网监听策略必须明确；首次安装、管理员尚未初始化时只提供经过授权的本地设置入口。管理员初始化后 Mac App 默认自动启用受账号认证保护的私有 IPv4 LAN HTTP（不绑定公网/所有接口），不强制 HTTPS；Mac 端可手动选择加密 HTTPS 或关闭访问，选择持久化。HTTP 传输密码、Cookie 和文件时不加密，只能用于可信家庭局域网，不能直接暴露到公网；无法绑定或无私有 IP 时显示错误，不回退到公网接口。
- 异地访问建议 Tailscale 等受保护网络；不默认映射管理端口到公网。
- **Cloudflare Tunnel 管理（可选，默认关闭）**：Core 可以监督本机已安装的 `cloudflared`（仅探测 Homebrew 白名单路径，不捆绑、不自动下载），将 `127.0.0.1` 上的 Web 服务暴露到公网。边界：不自研穿透协议；免费快速隧道无账号、随机临时域名、仅供测试；命名隧道需要用户自己的 Cloudflare API Token。API Token 只保存在 Mac 钥匙串（`dev.lightisle.tunnel`），经私有 IPC 在 Core 重启后重发，Core 仅在内存持有；Token/隧道 Token 绝不写入日志或审计。公网暴露后仍依赖既有登录限流与会话保护，开启前应确认账号密码强度并考虑在 Cloudflare Access 侧追加访问策略。
- **WebDAV（可选）**：同一监听器提供逐盘代次挂载。认证使用独立生成、首次显示、只存摘要的 WebDAV 密码（每用户最多 8 条）。Web Cookie 和 CSRF 请求头不提供 WebDAV 授权。认证失败按客户端地址限流。
- **设备配对尚未实现**；当前 LAN 访问依赖账号密码，手动选择 HTTPS 后另以自签名证书指纹校验；HTTP 没有证书指纹与传输加密，不能声称具备 Android 设备级撤销。
- 局域网监听在管理员初始化完成后由 Mac App 默认启用（可手动关闭），但仅在 App 持续运行时提供服务；一旦退出 App，立即停用 API 监听和运行中的 LightIsle 媒体任务。已有登录会话在未到期或撤销前仍按原认证规则处理。

- 登录、密码变更及分享密码等 HTTP 操作共享 4 个 Argon2 工作名额。满载时返回可重试的提示，同时保留各入口的尝试次数限制。网络测速读写均设传输期限，暂停传输的客户端不会长期占满测速名额。
- Bark 和 HTTP Webhook 只向配置的地址发送，不跟随重定向。通知配置错误不回显地址中的密钥，私有地址仍须显式允许，测试发送不会阻塞本机控制通道，退出 Core 时取消正在发送的通知。
- 命名隧道通过子进程环境传递令牌，Core 记录的子进程输出先拼接完整行再脱敏。Cloudflare API 拒绝跳转；外部工具版本探测和 FRP 配置读取均有大小限制，FRP 安装包同时限制下载和解压体积。
- 下载中心仅允许启用的管理员发起或恢复网络请求。aria2 会处理跳转、磁力和远端元数据，普通成员的文件写权限不能授权 NAS 代为访问任意网络地址。成员可查看、取消旧任务和恢复已下载文件的本地发布。

## 3. 文件安全

- 所有文件 API 只访问**用户登记的允许根目录**；规范化路径不能单独代替安全验证。已使用句柄级 `O_NOFOLLOW`/`os.Root` 校验。
- 文件 API、授权和 WebDAV 拒绝应用内部路径及其大小写别名。WebDAV 按每个根的目录授权和物理代次校验；私人目的地写入受目标所有者账本约束，其他成员的私人目录按授权过滤。元数据 XML 请求体限制为 64 KiB。
- WebDAV 目录查询支持 Depth 0/1，缺省只列一层，查询或复制最多 8,192 项。COPY/MOVE 拒绝重叠路径和目录同名覆盖，单文件覆盖须能原子交换并保存旧版。锁按物理根及代次隔离，每账号每根最多 64 把、最长 30 分钟。PUT 上限 32 GiB，COPY 上限 50 GiB，两者共用 3 个并发名额。
- Web 静态资源按目录句柄读取，符号链接无法越过 Web 资源目录。影院的 FFmpeg 探测、转码和字幕提取仅接受本地视频容器，禁用播放列表类输入和网络协议。
- 必须处理符号链接、硬链接、TOCTOU、跨卷移动、Unicode/大小写和 APFS 特性。符号链接与并发替换已有代码级防护；**单文件跨卷日志化安全移动已开发**（先校验并发布目标，再将源文件移入可恢复回收站），**目录级移动、持久续传和真实双盘故障验收仍未完成**；跨卷复制只发布校验通过的完整目标。
- 上传对文件大小、类型/内容处理、并发、磁盘剩余空间设置上限。当前有单文件 32 GiB 上限、4 MiB 客户端分块（后端 8 MiB 上限）和已提交偏移恢复。直传和分片每次写入前通过已绑定的 staging 文件描述符检查当前卷可用空间，并保留 64 MiB 基础余量。Core 内两类上传的空间检查和写入成对串行；空间不足返回 HTTP 507，不更改已提交偏移或覆盖目标。HTTP 文件直传和分片共用 4 个名额，停传会超时释放名额，分片可从已提交偏移重试。此项是预防性保护，不是储存空间预留：并行 SMB/其他进程写入仍可能抢占空间，写入失败仍走已有回滚；全局并发/空间配额尚未形成统一限制。
- 普通直传在打开的目录句柄上写入并发布，目标父目录被替换时拒绝发布。回收站移入、恢复和失败回滚使用排他重命名，避免覆盖并发创建的文件。
- 下载/媒体 Range API 也必须鉴权，不允许知道文件 ID 就越权访问。
- “删除原始文件”必须区别于“从图库/影视库中移除”；回收站与用户确认必不可少。
- 目录索引服务不能自动遍历私人系统目录、密钥目录和未授权卷。
- 图库缩略图是可重建的派生缓存，默认总量 1 GiB、可在 Mac 设置中调整为 256 MiB–8 GiB，并按最近使用淘汰；缓存目录位于应用私有数据目录，Web 无权修改容量，也不得把缓存当作原始数据备份。

- **Beta 诊断**只保存白名单事件字段。报错编号由 Core 生成，主机报告在 Mac 手动预览和保存。日志不收集凭据、真实文件路径、网络地址、正文或子进程原始输出。

## 4. 磁盘与电源安全

| 操作 | 默认策略 |
| --- | --- |
| 查看卷容量和状态 | 管理员允许，只读 |
| 浏览授权数据盘文件 | 按根目录与用户权限 |
| 从共享目录复制到其他磁盘 | 仅 Mac App 本机文件选择器；不覆盖、不删除源文件 |
| 跨卷移动 | 仅原生 Mac 有**单文件日志化安全移动开发版**；目录安全移动未完成；不得以“复制后永久删除”冒充安全移动 |
| 外置卷挂载/卸载 | 需白名单能力和失败提示 |
| 新建/修改数据卷 | 后期单独评审、强二次验证与目标盘比对 |
| 系统盘抹除/分区 | **永久禁止从远程 Web 管理界面执行** |
| 重启/关机 | 管理员再验证、有审计、警告运行中任务 |
| 远程开机 | 只能基于设备支持的电源恢复或外部硬件；不能虚假承诺 |
| 任意 root 命令 | **不提供此类 API** |

磁盘操作必须确认**稳定卷/设备身份**和实际选中设备，不能单靠动态的 `/dev/diskN` 标识或显示名称。对于无法明确识别目标的情况应拒绝操作。

## 5. 进程、容器与媒体

- Docker/Colima 属可选独立权限域；控制 Docker 引擎可能等价于宿主 VM 内高权限，务必限制访问。Mac 原生端已实现本地上下文限制、容器启停及镜像加速器配置初版，不提供远程 Web 端 Docker 操作 API；该功能尚未通过真实容器引擎的端到端验收，也不是本版本发布阻断项。详见 [本机 Docker 管理](LOCAL_SERVICES.md)。
- FFmpeg/Swift 读取媒体文件须限制允许路径、并发、CPU/内存/时间和临时目录大小。
- 影视刮削的第三方输入、海报和字幕是非可信内容，必须限制大小和下载地址，防止 SSRF 与注入。
- 对文件导入、封面生成、缩略图等不可信媒体处理隔离进程，崩溃后可恢复。
- 不从公开仓库或用户可编辑 Manifest 中执行任意安装脚本。

## 6. 日志、备份与更新

- 审计与运行日志分离；敏感内容脱敏、轮转和容量上限。
- 自动化任务目录替换后，旧调度拒绝执行，Web 设置也拒绝写入替换目录。Web 任务列表不返回脚本参数、环境文件名或本地邮件模板配置。
- **数据库恢复兜底**：SQLite 的账号、目录授权、私人相册/收藏与配置等不可再生元数据须有一致性备份与恢复能力；缩略图、影片自动索引及临时转码可再生成。Time Machine 应明确提示独立目标盘及内置/外置数据卷真实覆盖，不可假定开启即保护所有 NAS 文件。
- 读取回滚凭据时限制实际字节数。校验和复制备份文件时确认打开的是先前检查的普通文件，文件被替换后拒绝继续。
- 备份恢复在独立路径验证，并确认账号、ACL/授权根与物理卷身份正确；跨时间点的文件与数据库可能不完全匹配，应提供可再生索引重建和缺失项提示，不得自动删除原始文件。APFS 本地快照和 SQLite WAL 不能代替独立一致性备份。
- **备份恢复是所有者批准的离线元数据激活，不是自动灾难恢复。** 应用数据库激活需 Touch ID/登录密码验证并停止 Go Core；旧数据库保留在 `LightIsle-MetadataRollback-*`。中断激活保护和**成功激活后的离线元数据逆向回滚已有代码/自动化覆盖**，仍须真实设备演练。共享文件与数据库未提供跨资源联合切换：这是**个人版明确接受、并通过备份范围说明/手工核对/安全重扫处理的能力边界**，不再作为必须自研完成的功能。
- 安装和更新包进行签名校验；升级数据库前创建可回滚的安全点。
- 最小权限安装、可卸载、不擅自修改系统安全开关。
- 涉及外部共享/下载链接时设定过期时间和访问边界。
