# LightIsle 图库与影视体验原则与 P0 重构规范

> 版本：2026-11-08 · 设计与实现依据。本文是体验目标、交互契约和验收标准，不代表所有条目已完成；已验证能力以 `docs/STATUS.md` 为准，硬件验收仍以 `docs/DEVICE_ACCEPTANCE.md` 为准。

> 真实设备验收矩阵见 [真实设备验收清单](DEVICE_ACCEPTANCE.md)。

## 1. 产品定位与北极星

LightIsle 是个人与家庭使用的 NAS 客户端，不是文件管理器换一层皮，也不是电影元数据维护后台。用户打开图库，是为了回忆、找到、浏览和分享照片；打开影视，是为了尽快接着看或选择想看的内容。常用动作应在可见的上下文内完成，不需要理解「扫描、根目录、代际、转码队列、索引」等技术概念。

设计目标依次是：**内容优先 → 操作可预测 → 浏览连续 → 数据安全 → 多端一致 → 低资源开销**。不能用动画、复杂玻璃层、隐藏入口或功能数量换取所谓高级感。默认界面安静，细节可以丰富；高级操作按需出现而非占据首屏。

### 核心原则

1. **先内容、后控件**：照片墙和影视海报是视觉焦点。元数据和维护功能不抢占常态页面高度。
2. **一个位置承担一种职责**：一级导航定位内容；二级页面消费内容；上下文菜单处理对象；管理/维护入口只在必要时可见。
3. **动作靠近对象**：打开、分享、保存、收藏、移入相册或回收站在当前媒体可完成，无需回到首页。
4. **返回永远可预测**：关闭信息面板回到查看器，关闭查看器回到原滚动位置；切换筛选保留筛选语义，切换物理根必须重新确认授权。
5. **状态是内容而非弹窗轰炸**：上传、扫描、离线保存用非阻塞状态或任务中心呈现；失败时标清已完成、可重试、不可恢复，不出现假成功。
6. **危险操作明确数据边界**：移出相册 ≠ 移入回收站 ≠ 永久删除；个人收藏 ≠ 共享收藏；离线副本 ≠ NAS 原件。
7. **响应式而非放大版手机页面**：手机以全屏、底部面板与触控为主；平板采用分栏；桌面采用侧栏、键盘鼠标与就地信息面板。
8. **保留原件和正确权限优先于便利**：根身份 `rootID + generation`、账号 ACL、相册可见性、上传预占和播放进度保存不因界面改造而放宽。

## 2. 内容模型与导航信息架构

| 层级 | 图库 | 影视 |
| --- | --- | --- |
| 一级 | 时间线（默认）、相册、我的收藏 | 首页（继续观看、最近添加）、电影、剧集、历史 |
| 搜索 | 照片/视频名称；结果保持来源与筛选条件 | 电影/剧集名称；结果可直接进入详情 |
| 次级 | 年月跳转、地图、离线图库、手机备份、共享收藏 | 离线影片、本地播放、文件位置、扫描状态 |
| 对象页 | 相册内容、全屏查看器、信息抽屉 | 影片/剧集详情、季/集列表、独立播放器 |
| 上下文操作 | 选择、加入/移出相册、收藏、分享、保存、回收站 | 选择、分享、保存、重命名（授权）、回收站 |

**分类与行为必须分离**：电影与剧集是分类；继续观看是动态内容；历史是记录。图库「那年今天」是发现入口，不应与照片/视频格式筛选混为同一排标签。主导航一致使用「图库」「影视」，不混用「影院」。

## 3. 图库任务与页面契约

### 3.1 时间线首页与 Google Photos 体验对齐

- 顶部：标题「图库」，搜索、上传、选择、更多；主内容入口为「照片」「相册」「收藏」，特殊状态以可取消的筛选提示显示。
- **回忆与精选漫游卡**：时间线顶部常态提供「那年今日 / 星标精选 / 家庭佳作 / 动态影像 / 足迹地图」横向漫游卡，让用户无需搜索即可唤起时光回忆。
- **视图密度与全选**：支持「紧凑网格 / 舒适视图」密度切换，每个月份标题右侧支持一键全选/取消全选当月照片；EXIF 筛选面板支持按相机型号、是否含 GPS 定位及自定义起止拍摄日期范围多维筛选。
- 主体：按拍摄年月分组的紧凑正方形网格，手机默认约 3 列、平板 4–6 列、桌面按可用宽度自动增加；月标题与图片内容保持清晰层级。
- 「年月跳转」应在长时间线浏览时可发现，不必藏在条件苛刻的更多菜单里；跳转后新数据与标题对应。
- 手机、平板与桌面在**未筛选的完整时间线**使用边缘年月滑轨：手指、鼠标按住并滑动只更新浮动年月提示，松开后才请求对应服务端月份首项；边缘/越界位置必须钳制，不在每个经过的月份触发网络请求。切换根、筛选/搜索时不得误用全库月份序号；无年月索引、只有一个月或正在多选时隐藏滑轨，保留可访问的年月列表或下拉入口。键盘与读屏仍需可到达目标年月。
- 时间线跳转须能定位到**尚未分页加载**的历史月份，失败后保留现有照片、说明错误并允许重试；移动设备的侧边触控区不得遮盖主要内容，桌面超宽屏不能把单个空相册拉成巨卡。
- 搜索、筛选及进入查看器后返回，应尽力保持列表偏移、当前项目与搜索条件；仅在根身份变更、账号变化或数据确已失效时重置。
- 新上传应标识上传已完成 / 等待索引 / 已加入图库，而不是在扫描未完成时谎称已展示。刷新不中断当前查看。

### 3.2 相册与文件夹相册软链接

- 相册是独立、可返回的内容层级：相册总览整合文件夹相册、智能合集与私人/共享相册，使用封面、名称、项目数、私人/共享可见性标识；相册详情复用照片网格。
- Flutter 与 Web 均应拥有相册总览：按角色展示创建权限，私人/共享分类明确，不用一块巨大占位封面填充宽屏；新建、取消、返回与进入相册遵循同一导航语义。
- **真实文件夹相册**：新建文件夹相册在照片目录中建立真实目录，支持照片多选后批量复制或移动到文件夹相册；相册所有者可共享给同盘成员（默认只读、可选可写，可写计入相册所有者额度），在接收方建立受控相对软链接；接收方亦可主动退出共享（`DELETE /api/v2/photos/folder-albums/{name}/shares/me`）。
- 创建、重命名、添加照片、移出相册都围绕相册上下文操作；允许单张或批量添加，不要求逐张打开复杂详情表单。
- 「我的收藏」属于个人空间；「共享收藏」仅在权限允许时可编辑。管理员能力和普通成员视图须明确区别。
- 删除相册仅影响相册记录，不得暗中删除原始媒体；只有空文件夹相册允许被物理删除；任何涉及原件的操作必须明确告知。

### 3.3 全屏照片/视频查看器

- 点击媒体直接进入沉浸式查看：深色背景、内容居中、横向切换、图片缩放，单击显隐操作条；放大期间优先处理平移而非意外切页。
- 常用工具仅保留「返回、收藏、分享、信息、更多」；保存原件、离线保存、删除原件等分级放到上下文菜单或适配的大屏工具区。
- 详情是**同一查看器的上下文信息面板**：手机从底部升起、平板/桌面可使用右侧栏。信息面板里管理拍摄时间、文件大小、相册归属；关闭面板不能退出查看器。
- 先用小图迅速占位，再请求可用清晰原件；原件加载成功不得继续显示模糊缩略图。已访问媒体在相同账号和根代际范围内复用受限内存缓存。
- HEIC、RAW、Live Photo、图片视频混合浏览需要明确可用能力和降级信息；不提供伪造预览。离线副本和服务器原件应明确区分。

## 4. 影视任务与页面契约

### 4.1 内容首页与 Netflix 体验对齐

- **单行分类胶囊**：顶部收敛为单行 Netflix 风格分类胶囊（首页、电影、剧集、继续观看、观看历史、待匹配），状态切换清晰直接。
- **全宽巨幕 Billboard**：首页顶部提供响应式巨幕 Billboard（桌面与手机通用，复用海报内存缓存），直达主打影片的简介与播放。
- **进度与精选**：播放进度使用 Netflix 标志红（`#E50914`）高亮条；提供「TOP 10 高分口碑精选」大号描边序号横向海报栏与按压/悬浮微缩放反馈。
- 首屏优先「继续观看」：展示名称、剩余进度和直接续播入口；没有续播时不留空白区。
- 其后是「最近添加」「电影」「剧集」，通过清楚的分区标题与「查看全部」进入分类页；历史是次级记录入口。
- **增量刮削与待匹配**：扫描后自动衔接后台增量 TMDB 刮削；未匹配影视进入「待匹配」视图，并在此视图直接提供管理员 TMDB 增量刮削控制栏。

### 4.2 影片详情、剧集与播放器

- **沉浸式详情与 macOS 避让**：详情页统一采用 `IsleAppBar` 避让 macOS 交通灯区域；展示封面/背景、名称、时长、年份、简介、续播/播放主按钮；剧集详情支持按季筛选，影片详情页内嵌管理员元数据匹配面板（无需先播放视频即可导入本地 NFO、免凭据搜索豆瓣或在线搜索 TMDB 匹配）。
- 剧集详情按「剧 → 季 → 集」显示；当前集和下集突出，剧集切换不会让两个播放器控制器同时存在。
- 播放器独立于影片介绍页：打开即进入全窗口纯黑剧场舞台（不再受 400px 高度或浅色背景卡片限制）并自动播放；顶栏预留 macOS 窗口红绿灯安全间距，底部采用悬浮毛玻璃控制坞（支持自动隐藏、适应屏幕/铺满画面切换、原生窗口全屏 `F` 键、同目录播放列表及悬浮深色「播放信息与设置」抽屉）；时间轴、跳转、倍速、画质、字幕/音轨、上一部/下一部、同目录自动连播、画中画和投屏为播放上下文操作。
- **同目录播放列表**：无论是影视库播放器、本地离线播放器还是 Web 文件视频预览，均自动聚合同目录下的视频文件为播放列表（后端支持 `GET /api/v2/cinema?dir=<relative-dir>` 按成员目录授权过滤），提供「上一部 / 下一部」快捷切换、当前位置指示、悬浮播放列表抽屉及可选「自动连播」；切换视频前同样先保存当前观看进度并释放旧解码器。
- 返回或切集必须保存当前进度；保存失败要提供重试与明确的「仍然退出」选择，不得假装保存成功。
- 直接播放优先，不因设计重构引入强制转码依赖；失败时说明当前设备不能播放还是 NAS 缺少可选转码能力。

## 5. 统一交互、反馈与数据安全

| 场景 | 标准行为 |
| --- | --- |
| 点击缩略图/海报 | 照片进入查看器；电影进入详情；从「继续观看」可直接续播 |
| 长按/多选 | 进入显式选择模式，操作栏显示选中数量、全选范围、可执行动作和取消 |
| 搜索 | 清晰的输入与清除按钮；结果保留当前资源范围；返回恢复浏览上下文 |
| 查看信息 | 手机底部信息面板、宽屏右侧面板，关闭不丢失原位置 |
| 添加/移出相册 | 只更改相册成员关系，提示不影响原件 |
| 移入回收站 | 明确影响数量、对象和可恢复性；执行前确认；失败逐项报告 |
| 上传/扫描 | 任务中心持续跟踪；扫描完成后增量刷新，不打断查看 |
| 网络离线/磁盘离线 | 显示明确的失联状态与重试入口，不自动落入其他物理根 |
| 无权限 | 解释当前角色仅可查看或缺少写权限，不展示可点击但注定失败的按钮 |
| 账号/根切换 | 中止旧根请求、清理关联媒体与缓存，重查根代际、成员授权和播放来源 |

## 6. 布局与视觉规范

- 视觉层级：**媒体内容 > 当前页面标题/主操作 > 元数据 > 维护入口**。删除没有实际价值的复杂装饰、重复提示、套娃边框和重模糊。
- 标题统一：一级页面使用明确主标题；相册/详情页显示对象名与清晰返回。页面间距遵循 `IsleLayout`；相同语义跨页面使用同一组件。
- 手机：全屏二级页、可触及的主要操作、尽量单列元数据；平板：内容与信息并列；桌面：保留鼠标、键盘、悬停、ESC、左右方向键与滚轮浏览。
- 多选操作使用显式模式栏而不是突然改变所有入口；窄屏上按钮收敛为最常用动作加「更多」，禁止遮盖内容。
- 载入时使用与最终尺寸一致的骨架或低清预览；失败与空态不能混淆；屏幕阅读器有明确按钮标签；尊重系统大字体与减少动态效果。
- 保持低资源开销：列表懒加载、可控缩略图尺寸、有界缓存、后台停止无意义请求、只保留活动播放器。

## 7. 实施边界

### P0（本轮）

1. 全页审查与可复现任务路径、交互设计样板。
2. 图库/影视导航清晰化；图库时间线、相册、收藏与影视内容首页按信息架构呈现。
3. 图片查看器的内容优先、信息面板与高清缓存；影视详情/播放职责分离，续播与剧集操作更直接。
4. 搜索、选择、批量、原件安全、离线错误与任务状态的一致反馈；增量回归测试。

### P1（后续，不得冒充 P0 完成）

- Web/Flutter 更广范围视觉对齐、性能分析与极大媒体库压力测试、真机原生投屏/PiP/Live Photo/RAW 验收、真实双盘热拔插矩阵、完整无障碍审核。
- 图库本地 Vision AI（OCR/双语场景/私有人物聚类/连拍相似清理）已在 `LightIsleMediaWorker`、`core/internal/gallery`、`/api/v2/roots/{rootID}/photos/*` 路由及 Web/Flutter 人物相册、实况文本卡片、相似废片二次确认清理界面完成闭环，真实万张级家庭图库聚类质量与持续负载温控列为 P1 实机验收（详见 [STATUS](STATUS.md)）；音乐库与企业级权限工作流不属于本轮。

## 8. 完成定义与用例清单

| 旅程 | 最低验收条件 |
| --- | --- |
| 图库 → 打开照片 → 信息 → 返回 | 信息关闭仍在原照片，查看器关闭回原滚动位置、原筛选条件 |
| 时间线 → 指定年月 | 可发现入口、准确载入年月首项、继续分页不重复 |
| 相册 → 添加/移出 | 操作对象明确、可见性正确，不改变原文件；取消不产生修改 |
| 查看照片 → 返回 → 再次打开 | 清晰度不倒退，缓存只在有效账号/根代际复用 |
| 影视 → 继续观看 | 首页可直接续播，退出可恢复上次位置；播放失败有重试 |
| 剧集 → 选季选集 → 切换 | 集数正确、旧播放器释放、字幕/进度状态不串集 |
| 多选 → 分享/保存/删除 | 按权限启用，正确处理部分失败；删除有明确确认 |
| 拔盘 / 换盘 / 断网 | 不读取或写入另一块盘，不误报文件删除，错误状态可恢复 |
| 各设备尺寸 | 手机、平板、桌面 UI 不溢出，关闭/返回/键盘操作有效 |

验证必须记录：Widget/单元/集成测试、构建结果与真实设备验收是不同证据。代码或模拟器通过不能代替真实 iOS/Android、物理双盘、DLNA/投屏验收。

## 9. 代码边界与建议职责

- `apps/flutter/lib/features/media/` 保持照片与影视独立页面，但共用筛选/选择/媒体展示/操作契约和 UI token。
- 图库内容状态（timeline、album、favorite、query、scroll anchor）与媒体查看状态（item、zoom、chrome、detail pane）分离，防止二级页面反向修改主页根身份。
- 影视内容状态（section、query、film detail、episode list）与播放器会话（controller、seek、subtitles、cast、save queue）分离；切集必须先结束旧会话。
- Web 复用相同的产品语言和状态模型；不强迫 Flutter 与 Vue 使用相同视图框架或生成两套业务规则。
- 所有根 API 必须保留 `rootID + generation` 与权限验证；资源缓存必须按会话/账号和物理根作用域隔离。

## 10. 记录方式

每一批实施需说明：改变的用户旅程、变更文件、功能迁移/保留、通过的测试、未验证的真机边界。先解决 P0 任务的闭环，再决定是否进入 P1。实现现状不回填成设计承诺，避免文档与代码不同步。

## 11. 媒体质量与回归守则

- 「最近添加」严格使用服务端最近入库排序；「继续观看」严格使用当前账号未完成的播放进度。接口失败不能用按标题排序的数据冒充。
- 打开照片先展示清晰度受限的占位图，再显示原件；不能在原图下载/解码完成前把可见照片替换成黑屏转圈。
- 移出相册只修改关联；移入回收站明确需要原文件权限和确认；不能把两者混成同一操作。
- 根切换会取消/丢弃旧根媒体查询与预览，切换账号不复用他人的缓存与观看历史。
- 缺乏真实设备/媒体/账号时，只能标记为「软件实现与自动化完成，真机待验」，不能写「全验收通过」。相关设备项见 [真实设备验收清单](DEVICE_ACCEPTANCE.md)。
