# LightIsle 当前开发路线图

> **2026-10-27 Flutter 移动交互更新**：五栏页面与通用二级页布局统一；照片、影院、文件手动上传和分类文件管理入口已补齐，重命名、返回上级、多选及上传退出保护已落地。后续聚焦真实 Android/iOS 系统选片、iCloud/Live Photo、长视频、离线硬盘及切后台行为验收，不再将“增加 Flutter 上传按钮”作为待实现项。配额和后台备份边界不因界面重构改变。

> **2026-10-27 API 里程碑更新**：全项目 HTTP 客户端和 Go 路由升级为唯一 v2，删除旧 v1 路由，不做旧客户端兼容或迁移；`/api/v2/roots/{rootID}/...` 与全局 `/api/v2/...` 分别承担有根范围/无根范围请求。后续 P0/P1 应聚焦写入渠道配额、实机磁盘断开和手机后台验收，不再安排“支持旧版 v1”的兼容工作。

> **2026-10-27 Android 备份与 Flutter 三端范围修订**：Android/iOS 共用前台照片 v2 上传链路；Android Kotlin WorkManager 已改造成绑定 rootID/generation 的多硬盘后台任务，旧无根身份任务需重新启用。macOS 共用 Flutter 多根访问层，但无手机相册后台源；iOS 后台调度尚未开发。待真机验证：Android WorkManager 长时任务、网络/硬盘离线与恢复、外盘换盘、iOS 退后台；服务端 v1 的认证/管理等剩余接口另行分模块迁移，不能直接移除。前期“Android 后台尚未实现”的记录为改造前状态。后台多盘代码完成不等于发布验收完成。

> **2026-10-27 最新进展**：Web/Flutter 文件、图库、影院导航已基于登录用户三类存储绑定自动选盘，并处理硬盘离线/代际变更；普通成员一份跨盘账本和默认 100 GiB 继续沿用，管理员不限额；管理设置可按需核对在线文件占用但不改动账本。手机前台照片备份已改用个人照片绑定；旧 Android 后台 WorkManager 为防误写被停用，**多根后台任务尚待实现**。不支持的私人写入渠道继续拒绝，`enforcement=pending` 不解除；全渠道配额及实盘手机验收仍在后续阶段。以前的“自动路由未实现”记录属于本次修改之前的状态。

> 本文只维护**未来开发及其完成条件**，不再重复最初 M1–M7 的历史勾选任务。现有代码与缺口看 [STATUS](STATUS.md)，产品范围看 [fnOS 个人版定位](FNOS_PARITY_PRIORITIES.md)，真实设备验收看 [验收清单](ACCEPTANCE_DEBT_2026-10-25.md)，发布底线看 [PRODUCTION_RELEASE](PRODUCTION_RELEASE.md)。

## 优先级

**优先补现有功能闭环，不继续铺新菜单。** NAS 后端仅 macOS arm64；Flutter Android/macOS/iOS 为已有独立用户客户端。代码/自动化通过不等于外置硬盘、真实手机、发布公证通过。

**2026-10-26 家庭版最终备份范围**：仅保留应用配置/SQLite 备份（每周、最近 5 份）与管理员确认的配置恢复；整盘手动快照、整盘恢复、逐根每日/每周计划已从产品和原生 IPC 路由撤销，历史快照原件不自动删除。原始文件请使用 macOS Time Machine 或用户自选的独立备份工具。

**2026-10-27 修复阶段说明**：Web 回收站说明与列表渲染、Flutter 显式根切换与根代际隔离、管理员人工放弃已移除旧根、图库“那年今天”/年月跳转、影视手动/自动下一集，以及同根私人已入账普通文件移动的账本预占均已进入开发工作树。**仍有 P0**：WebDAV/下载写入私人目录的统一计费、分类自动寻址与跨根原片权限/容量验证（未支持部分继续拒绝）；**仍有 P1**：手机 Live Photo/大原片和后台备份、真实字幕/连续播放/磁力与中断恢复、真实设备验证。不应把本轮单测当成这些项目的验收。

**2026-10-26 多根产品转向**：面向**全新安装，没有历史用户数据需要迁移**。每个账号有固定的私人文件/照片/视频位置，各类别可在不同硬盘，管理员无限应用配额，其余角色默认跨根合计 100 GiB。用户存储绑定时会通过根租约创建三个分类中的指定专属目录，并给成员原子授权；Web 新建账号若已选中在线多根则依次初始化三类，Web/Flutter 已有配置界面，Mac 多根页引导至 Web。**仍未实现统一硬配额、实际用量及全路径自动路由，API 保持 `enforcement=pending`**。详见 [ADR 0003](adr/0003-personal-homes-and-quota.md)。

**2026-10-26 家庭使用再简化**：磁盘离线时只提示检查连接、重插原盘；确实坏了或不用时，由管理员在 Mac **移除旧登记**，在 Web 对每个受影响类别点击**放弃旧空间并重建**，再选新盘创建空白目录。旧文件不删除、不迁移；不做企业级自动磁盘修复、周期全盘校准或复杂多盘恢复系统。个人目录单文件复制已接入预占/入账，已落盘但提交结果不确定的预占保留；管理员可只读查看待对账记录。

## 完成定义（DoD）

1. 用户入口、权限、API/本机私有 IPC、SQLite/文件落盘及错误反馈完整一致，旧客户端可以合理降级。
2. 文件操作不覆盖原件，离线/中断时保留源文件；账号、授权和私人相册等不可再生数据具有真实可验证的恢复策略。
3. 测试包括授权拒绝、竞态、取消、中断与恢复；列出实际测试命令，静态检查和构建通过。
4. 涉及外接盘、浏览器解码、手机后台和 Apple 系统签名的功能，必须额外在真实环境留下日期、版本、日志/截图及介质数据，不以模拟测试冒充。
5. 只在 [STATUS](STATUS.md) 维护代码现状；[验收清单](ACCEPTANCE_DEBT_2026-10-25.md) 维护真实测试结果，产品范围更新 [FNOS_PARITY_PRIORITIES](FNOS_PARITY_PRIORITIES.md)，不可逆架构决定写 ADR。

## 明确不做

不自研 RAID/Btrfs/ZFS、企业级跨盘事务、文件+SQLite 联合灾备、完整通用任务持久队列或第二套块级增量备份。复用 macOS APFS、SMB、Time Machine、FSEvents、SQLite，Docker/FFmpeg/外部服务保持可选。软件不能保证 Mac 完全关机或 FileVault 未解锁时自行提供 NAS。
