# M5 本机 NAS 运维：手动文件备份与 SMB 诊断

> 本文是个人 NAS 的备份与离线恢复操作说明。v2 快照包含 SQLite 账号、图库、影视、任务与部分设置；文件恢复只写入隔离目录、数据库激活需停止 Core 并获得 Mac 所有者授权。已开发成功激活后的**独立离线元数据回滚**，不代表文件也会一起恢复到相同时间点。macOS Time Machine 的真实原片备份覆盖须由用户独立核实；不自研企业级跨文件/数据库联合灾备。实盘恢复、签名与 GUI 仍须按 [发行门禁](PRODUCTION_RELEASE.md) 验证。

## 定位与权限边界

- **Mac 原生 App**（SwiftUI）是唯一执行本机系统与备份管理操作的入口。首次创建管理员、系统监控、共享文件夹授权、备份与恢复都走私有 stdin/stdout 子进程通道。
- **Web 用户端**继续只承载文件、图库、影视与普通账号管理。Go HTTP 服务**不注册**备份、恢复、macOS 文件共享配置或系统关机 API。
- 不需要 sudo/root，不调用 `systemsetup`、`sharing -e` 或任意 Shell。SMB 只检查 Mac 本地 127.0.0.1:445 是否接受 TCP 连接（诊断，不是共享成功证明），用户可自行打开 macOS 系统设置配置文件共享。
- 后端仅 macOS arm64；Mac App 退出后取消活动备份任务，后端随应用退出。

## 在 Mac 上创建文件备份

1. 打开 `LightIsle.app`，完成首任管理员初始化，在「存储」中设置当前共享文件夹。
2. 选择「创建文件备份…」，在 macOS 文件夹选择器中指定独立的备份目标文件夹。建议使用与数据盘不同的外置硬盘。
3. Go Core 在目标目录下创建 `LightIsle-Backup-时间-ID` 快照文件夹；包含 `manifest.json`（相对路径、大小、SHA-256）和 `data/` 下的文件副本。
4. Mac「存储」页面显示正在处理的文件数、字节数与结果目录。完成后请自行再保留一份不同设备/位置的备份。

**安全约束：** 源目录与备份目录不能互相包含，目标必须在当前 Mac 用户主目录的子目录或 `/Volumes/` 外置卷下。备份跳过指向根目录外的符号链接，按文件流式复制，单次任务最多 20,000 个条目、50 GiB；异常时删除不完整临时备份文件夹。不会修改原文件。

## 在 Mac 上恢复

恢复前可先在「存储」页点击「查看备份…」，选择存放快照的父目录。清单展示日期、文件/元数据版本、manifest 声明容量和异常状态；只读取有界数量的清单，不会删除快照。**“清单可读”表示内容尚未做 SHA-256 校验**，不能据此保证可恢复。目录较大或清单超限会明确提示本次检查不完整；恢复时仍逐文件重算哈希。

1. 选择「从备份恢复…」，在选择器中指向一个完整的 `LightIsle-Backup-...` 快照文件夹。
2. Go Core 先检查 `manifest.json` 的版本、路径合法性、条目数量和容量；恢复时逐文件重算 SHA-256。
3. 验证通过后，数据原样写入**当前共享目录下新建的** `LightIsle-Restored-时间-ID`，包含原始相对目录结构。
4. 原有文件不会被覆盖；出现损坏文件/权限不足/外接卷离线，会保留原始数据并清理正在写入的恢复临时目录。

### 离线恢复账号及设置数据库

文件恢复成功后，Mac「存储」页将显示元数据隔离目录，并提供「验证 Mac 所有者身份并离线应用数据库」入口。必须通过 macOS Touch ID 或登录密码确认。App 将停止 Go Core，再用内置 `lightisle-recovery` 验证 SHA-256、SQLite `quick_check` 和必需的数据表；确认安全后，将之前的应用数据库移到私有 `LightIsle-MetadataRollback-*`，再原子替换为已校验数据库。原 Web 登录会话不会恢复。**不要将恢复当作合并操作：新的账号/设置将替代旧数据库中的内容。**

离线替换使用磁盘恢复日志，异常中断时 Go Core 会拒绝进入工作状态，Mac 错误页可以在设备所有者确认后选择「修复上次中断的数据库恢复」恢复旧数据库。旧 SQLite `-wal`、`-shm` 尚存在时会拒绝激活，避免新数据库附着到旧 WAL。正常完成后旧数据库仍保留在 `LightIsle-MetadataRollback-*` 供人工检查。**成功激活后的元数据回滚已由独立恢复工具实现**：关闭 App/Core 后通过 `lightisle-recovery --operation list` 核对可回滚事务 ID，再用 `--operation rollback --transaction-id <ID> --confirm ROLLBACK_OFFLINE_METADATA` 执行，仅允许符合回滚条件的事务。它**不会反向移动或合并共享目录文件**，不能当作文件+数据库联合灾备；操作前请保留另一份完整备份，并逐项核实实际事务。安全操作前提与完整命令见 [PRODUCTION_RELEASE.md](PRODUCTION_RELEASE.md)。

## 可选自动备份

- Mac「存储」页面可选择「每天备份」或「每周备份」及目的文件夹，也可以随时关闭。计划存储在私有应用目录的 `backup-schedule.json`（权限 0600），**禁止提交到 Git**。
- 计划只由正在运行的 Go Core 每分钟检查；首次启用时从设定时刻算 24/168 小时，下次运行时间、目标目录、上次尝试与调度失败原因可在 Mac 界面看到。应用完全退出、电脑休眠时均不会执行备份，也不会另启 launchd 守护进程；错过的时间不会自动补齐。
- 同时只允许一个备份或恢复任务。定时备份保留完整快照，**当前不会自动清理旧快照**；请关注备份盘剩余空间，定期手动整理。

## 首版范围与不包含内容

- **共享目录与私有元数据快照**：v2 备份共享普通文件/文件夹，另外包括 `accounts.sqlite`、`gallery.sqlite`、`cinema.sqlite`、`tasks.sqlite`、`shared-root.json`、`backup-schedule.json`（如果存在）；SQLite 通过一致性导出。**不包括** 回收站内部数据、Docker/Colima 数据、完整 macOS 系统配置。数据库支持本机离线激活、中断修复以及符合条件的独立元数据版本回退，但共享文件不会合并到原目录，不能当作完整的系统灾难恢复工具。
- **定期全量任务**：支持可选的每日/每周调度，但尚未提供增量去重、加密归档、限速、快照轮换、断点恢复或跨设备备份。
- **无原生 SMB 配置变更**：不自动开启共享、不修改用户账户、共享密码和 ACL。 macOS 系统设置里的「文件共享」由用户决定。
- **非真实文件系统快照**：复制期间编辑原始文件可能导致任务失败或文件版本不同；建议备份前暂停大量写入。

## 验收状态

- 自动化覆盖（Go 测试）：不重叠路径、源数据不覆盖、备份与恢复的 SHA-256、恶意相对路径拒绝、符号链接逃逸跳过；离线激活的校验、旧 WAL 拒绝、中断恢复与回滚；计划持久化与停止。
- 自动化覆盖（打包后 `tests/test_native_backup.py`、`tests/test_native_recovery_bundle.py`）：模拟 Mac 本机私有 IPC 创建/恢复临时文件，恢复隔离目录，离线元数据验证/激活/中断回滚，Web HTTP 禁止发起备份，SMB 只读探测，父进程管道结束即退出。
- **人工验收待完成**：Mac GUI 手动选择器、Touch ID/登录密码真实弹窗、外置盘拔插、10 GiB 级真实文件、断电与空间不足故障注入、真实多用户 SMB 网络环境、成功激活后的独立元数据回滚真机演练。文件+数据库联合灾备不属于个人版开发承诺。
- 跨卷**安全复制**属于存储页能力，不是备份功能；它只复制、不删除源文件。已有受控的跨卷单文件移动流程不能替代备份目标选择或自动媒体备份。

## 2026-10-22 调度诊断与任务历史

定时任务在启动前会检查目标目录是否仍可用、是否被改成指向别处的符号链接、是否与源目录重叠。无法派发时记录上次尝试和失败原因，保存下次周期，不每分钟重复静默尝试；用户可修复目录后手动立即备份，或等下次周期。任务已经派发后的复制/校验错误仍显示在“上次备份任务失败”，与调度错误分开。计划配置通过私有临时文件同步、原子替换和父目录同步保存。此检查不等同于备份目标卷稳定身份校验；同路径替换卷的完整保护仍列在个人 NAS 后续计划。

后台图库、影视、备份运行记录现保存到 `tasks.sqlite` 的 `task_runs`，管理员可以在 Web 任务中心分页查看。保留最近 1000 条及仍运行的记录；早期版本只有每类最新摘要，升级不会凭空补造旧历史。新表随现有 SQLite 一致性备份一起导出；恢复旧版数据库后会重新建表。

备份内的任务历史只保存当时已结束的运行记录；归档副本中的进行中记录被排除，对应摘要标记为“备份时尚在运行，恢复后需手动重新开始”。此操作只处理快照副本，不修改活跃任务数据库，也不把本次尚未完成的备份伪造成成功历史。
