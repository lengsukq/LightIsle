# LightIsle 个人 Beta · 硬盘基础管理共用层

## 范围与架构

**一套磁盘管理核心，两种客户端。** Go Core `core/internal/diskmgmt` 负责 macOS 硬盘只读探测和受限操作。管理员 Web 经鉴权且 CSRF 防护的 `/api/v1/admin/disks` 使用该 Core；Mac 原生界面经仅父进程可访问的 stdin IPC 使用同一个 Core 服务，不另写 Swift 磁盘操作引擎。

面向个人 NAS 的 MVP：外置盘名称、设备 ID、卷格式、容量/剩余、是否只读、SMART 原始状态（不虚构健康百分比）、连接协议/挂载情况；重命名、挂载、卸载/安全弹出。格式化继续打开系统「磁盘工具」并由 macOS 自己执行系统确认。

## 保护与验收

1. **最小权限**：普通账号无权浏览详细设备、发起挂载/更名/弹出。Web 要求管理员会话 + 同源自定义请求头；Mac UI 仅通过可信父进程 IPC 调用。Core 不接受路径作为执行参数、不借 shell 解释用户数据、不自动提权。
2. **失败封闭**：修改操作之前重新读取设备身份，要求完整 UUID（能取得时）和设备 ID、外置、卷属性吻合；系统盘、内部磁盘、整盘设备、挂载至异常位置或用于当前 NAS 根（含离线根）的磁盘禁止相关危险操作。所有 diskutil 操作有超时、输出限额和并发串行限制。
3. **卸载/安全弹出**：只对明确选中的外置盘操作；如果卷正在用于 LightIsle 共享存储或 Core 任务，拒绝操作。底层 macOS 返回 busy 时不要强制卸载/弹出。
4. **重命名**：限制卷名长度、控制字符、斜杠和特殊名称，拒绝路径注入；操作返回后刷新卷列表，路径变化时禁止绕过已绑定目录的身份检查。
5. **挂载**：只能挂载经系统 `diskutil` 列出的已知外置卷设备，不能通过客户端传任意路径或磁盘命令。无效/模糊/未识别设备拒绝。
6. **验收**：测试包括冒充管理员、恶意磁盘 ID、路径穿越、系统盘、自用盘/后台任务拦截；不对真实外置硬盘执行挂载、卸载、重命名或擦盘，实盘验收需单独人工进行。

本轮不做企业级 SMART 长期历史、硬盘温度百分比、低层磁盘修复、自动重新挂载、RAID 或格式化引擎。未能可靠获取的 SMART 显示「未知/设备不支持」，不等同健康。

## 安全交互说明

- 用户点击前端「重命名/挂载/安全弹出」，由统一 Core 使用经过验证的真实设备标识执行 macOS 自带磁盘工具，不执行任意命令行、提权或格式化；设备身份发生变化时操作被拒绝。
- Eject 使用 macOS 常规弹出，不开启 force；被 LightIsle 主共享目录、注册根或备份配置引用的卷拒绝危险操作。由于系统其他程序也可能占用卷，macOS 本身仍会拒绝 busy 状态。
- 页面只展示系统可读的 SMART 原始状态（Verified / Failing / Not Supported / 未知），不伪造健康百分比。SMART 读取不可用不等于硬盘健康。
- 当前单根、多根预览及离线盘清理仍按原有策略运行；这一功能不会偷偷迁移用户真实文件。
